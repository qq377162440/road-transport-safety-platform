## 一、本盒文件的定位与结论先行

这份文件是**盒二（制度大类）的普货通用版**，结构上分两大板块：

| 板块 | 内容 | 数量 | 性质 |
|------|------|------|------|
| **制度板块** | 安全生产责任制 + 13 项管理制度 | 14 份制度 | **通用**（所有普货企业一套） |
| **规程板块** | 驾驶员操作 + 车辆检查 + 装卸 + 消防 + 动态监控 | 5 类操作规程 | **通用 + 可附加**（按车型/货物类别的差异以"规程和附件"形式挂在后面） |

> **关键结论**：这份文件印证了用户之前定稿的分类逻辑——**普货 = 1 套通用安全管理制度 + 按车辆作业特点设置的专项操作规程**。其中 14 份制度是"通用层"，5 类规程里"驾驶员操作规程"和"装卸操作规程"是"通用层"，"车辆日常检查""消防""动态监控"需按车辆结构（大型货车 / 牵引车）做差异处理。

## 三、与既有设计的对齐验证（核心）

### 3.1 印证：普货"1 套通用 + 专项规程"成立

用户之前定稿的分类（文档 09 第十章）：

> 普货：1 套通用安全管理制度，按车辆作业特点设置专项操作规程。

本盒文件完美印证：

- **通用层** = 14 份制度 + 4 类通用规程（驾驶员操作、装卸、消防、动态监控）
- **专项层** = 车辆日常安全检查规程（按车辆结构分"大型货车 / 牵引车"两套检查表）

### 3.2 印证：车辆类型 7 大类的拼装落点

文档 09 已定义普货 7 大类（G1 厢式及封闭 / G2 栏板及仓栅 / G3 集装箱及牵引 / G4 自卸及工程 / G5 罐体及散装物料 / G6 平板及大件 / G7 专项功能）。

**本盒文件揭示的拼装真相**：

1. **制度层不随 7 大类变化**——14 份制度对所有普货企业都一样，拼装时只需生成 1 套。
2. **规程层只有"车辆检查表"随车辆结构变化**——而且本盒只分 2 类（大型货车 / 牵引车），不是 7 类。这意味着：

> **待决策点 A**：车辆检查表到底按"7 大类"细分，还是按"车身结构 2 类（普通货车 / 牵引车+挂车）"细分？

从本盒实际内容看，检查表的差异是**车身结构驱动**（牵引车有挂车、牵引销、制动管路连接等独有项），而非"厢式 vs 栏板"这种上装差异驱动。建议：**检查表按"车身结构"细分（普通货车 / 牵引车挂车 2 套），其余 7 大类只影响"装卸注意事项"的附加条款**（如自卸车的举升安全、罐体车的装卸接口、集装箱的锁扣等）。

### 3.3 印证：范本三层架构落地

文档 09 定义三层：系统级范本组（超管）→ 企业范本（可个性化）→ 生成台账。

本盒文件对应关系：

| 三层 | 本盒对应 |
|------|---------|
| 系统级范本 | 这份"乐从区域通用版"就是**系统级范本组**的普货·通用版种子 |
| 企业范本 | 企业可在此基础上改公司名、岗位人员、个别条款 |
| 生成台账 | 填充变量后生成的 14 制度 + 5 规程 PDF |

> **待决策点 B**：用户说"以后还会发不同区域的模板"。这引入了一个**新维度——区域**。需要确认：不同区域模板的差异是"仅公司名/落款不同（可归入变量）"，还是"条款实质不同（需独立范本组）"？建议先按"区域=范本组的一个分组标签"处理，等第二份区域模板到手后做差异对比再定性。

### 3.4 印证：字段字典扩充

本盒文件暴露了大量新变量，需补入字段字典：

### 3.5 岗位内容库的扩充（关键）

文档 09 已建 `org_post_content`（职责/目标/危害三部分）。本盒文件把"目标"部分极大丰富了：

**普货岗位分解目标标准结构**：
- 责任事故控制指标（6 项）：一般以上事故 0 宗、百万车公里频率≤3、死亡率≤0、重伤率≤0、经损率≤3.5万、无火灾
- 运输安全管理工作指标（8~11 项）：职业病防护 100%、卫星定位安装 100%、持证上岗 100%、培训合格 100%、隐患治理 100%、车辆年检 100%、二级维护 100%、安全经费 100%、应急演练≥3 次等

> **待决策点 C**：这些"百万车公里频率≤3、经损率≤3.5万"等指标是**行业通用标准值**还是**企业可调**？建议：作为岗位内容库的**默认值**，企业可在个性化层覆盖。

## 四、范本改造定性（沿用盒一的"增减型/替换型"规则）

### 4.1 14 份制度的定性

| 制度 | 定性 | 理由 |
|------|------|------|
| 安全生产责任制 | **替换型（按岗位）+ 增减型（岗位内）** | 5 岗位职责整段不同→按岗位独立；但岗位内"目标+职责"结构一致→可单范本循环 |
| 监督检查制度 | 增减型（单范本） | 仅岗位名不同 |
| 教育培训制度 | 增减型（单范本） | 同上 |
| 驾驶员管理制度 | 单范本 | 无岗位变量 |
| 车辆安全管理制度 | 单范本 | 无岗位变量 |
| 应急救援预案管理制度 | 增减型（单范本） | 岗位名不同 |
| 考核与奖惩制度 | 增减型（单范本） | 岗位名不同 |
| 事故报告统计制度 | 单范本 | 无岗位变量 |
| 动态监控管理制度 | 增减型（单范本） | 岗位名不同 |
| 风险分级管控制度 | 单范本 | 无岗位变量 |
| 隐患排查治理制度 | 增减型（单范本） | 岗位名不同 |
| 安全费用管理制度 | 单范本 | 无岗位变量 |
| 劳动防护用品制度 | 单范本 | 无岗位变量 |
| 台账档案制度 | 单范本 | 无岗位变量 |

> **总结**：14 份制度里，**13 份是"单范本（增减型或纯通用）"，只有"安全生产责任制"1 份是"替换型（按岗位）"**。这大幅降低了范本改造工作量。

### 4.2 规程板块的定性

| 规程 | 定性 |
|------|------|
| 驾驶员操作规程 | 单范本（通用） |
| 车辆日常检查规程 | **替换型（按车身结构：普通货车 / 牵引车）**，且含 3 张检查表（出车前/行车中/收车后） |
| 装卸操作规程 | 单范本（通用） |
| 消防设备操作规程 | 单范本（通用） |
| 动态监控操作规程 | 单范本（通用） |

> **关键难点**：车辆日常检查的 3 张检查表是**表格型内容**（35~47 项检查项 × 检查要求 × 大型货车√/牵引车√），这是范本引擎**首次遇到表格变量**。文档 09 目前的变量类型只支持"标量/条件段/列表"，需要**新增"表格变量"类型**。

### 4.3 表格变量的处理（新增设计）

车辆检查表是结构化表格，建议用"列表变量 + 表格渲染"处理：

```html
<table>
  <thead><tr><th>序号</th><th>检查项目</th><th>检查要求</th><th>大型货车</th><th>牵引车</th></tr></thead>
  <tbody>
    {{#each check_items}}  <!-- 表格列表变量 -->
    <tr>
      <td>{{seq}}</td>
      <td>{{item_name}}</td>
      <td>{{requirement}}</td>
      <td>{{truck_flag}}</td>   <!-- √ 或 × -->
      <td>{{tractor_flag}}</td>
    </tr>
    {{/each}}
  </tbody>
</table>
```

> **待决策点 D**：检查表的"√/×"差异（牵引车多的 2 项：牵引销连接、挂车制动管路）是**存完整两份表**，还是**存一份表 + 每行标 truck/tractor 适用标记**？建议后者（一张表 + 适用标记），新增车型时只需改标记，不重做整表。

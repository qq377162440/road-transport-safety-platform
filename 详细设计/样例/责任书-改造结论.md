# 责任书范本改造样例 - 结论与修正建议

> 配套文件：`样例/责任书-范本改造样例.html`
> 日期：2026-10-27

---

## 一、样例做了什么

把盒一里 6 个岗位的《安全生产责任书》合并成**一个 HTML 范本**，用：
- `{{变量}}` 填充企业名、人名、岗位、日期等
- `{% if post == 'xx' %}` 条件段落承载岗位间差异

## 二、样例暴露的关键问题

改造过程中发现，这 6 份责任书的岗位差异**远超"条件段落"能优雅承载的范围**：

| 差异维度 | 实际情况 |
|---------|---------|
| **标题** | 主要负责人="安全生产**目标**责任书"，其他="安全生产责任书" |
| **签订关系** | 主要负责人：公司↔负责人（**单边**）；安全员/监控员/行政财务：安全主要负责人↔X（**双边**）；驾驶员：安全员↔驾驶员（双边） |
| **签字栏结构** | 单边（盖章+签字）vs 双边（责任管理人+责任人两栏） |
| **安全目标** | 各岗位指标条数、内容均不同（11条/7条/5条/5条/8条） |
| **安全职责** | 完全不同整段（14/16/10/21/12 条，几乎无重叠） |

## 三、核心结论：方案 B 需要"细化粒度"

原方案 B 的"单范本承载所有岗位"，在责任书这类范本上会退化成**"一个 HTML 文件里塞 6 套整段内容 + 一堆 if"**。技术上可行，但：

1. **单文件巨大难读**：6 个岗位的职责+目标全塞一起，范本文件上千行，维护时极易改错岗位
2. **维护不省事**：改某个岗位的职责，还是要在一堆 `{% if %}` 里精确定位，并不比"改独立范本"快
3. **条件逻辑复杂**：签订关系（单边/双边）、标题、签字栏结构都要用条件判断，可读性差

## 四、修正建议：**"结构相同才合并"** 的分层策略

| 情况 | 做法 | 适用 |
|------|------|------|
| **条款结构完全一致，仅岗位名/人名不同** | 单范本 + `{{post}}` 变量 | 任命书（5个岗位几乎只差人名岗位名） |
| **结构相同，部分段落有岗位差异** | 单范本 + `{% if %}` 条件段 | 岗位告知书（主体结构同，驾驶员危害描述更详细） |
| **整段替换、签订关系/签字结构都不同** | **保留按岗位独立范本** | 责任书、承诺书 |

**即：方案 B 用于"同构"范本，方案 A 用于"异构"范本。** 判断标准只有一条：**岗位间是否"整段替换 + 结构变化"**。

## 五、对《09》文档的修正

原《09》文档 4.3 决策记录"方案 B：单范本"需修正为：

> **方案 B'（分层）：结构相同的范本合并为单范本（岗位做变量/条件段）；整段替换且签字结构不同的范本，保留按岗位独立范本。** 由范本改造时逐个判断，判断标准是"岗位间差异是'替换'还是'增减'"。

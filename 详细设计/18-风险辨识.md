> 所属域：risk（风险辨识）
> 优先级：**P1 刚需**（需求文档二期；档案盒「盒八·风险分级管控与隐患排查治理」（普货）/「盒九」（危货）为政府必查项）

> 上游依赖：01 组织权限、03 企业信息、06 组织架构（岗位）、09 范本引擎（模板 + 一键签名）

## 一、模块定位

风险辨识是"**事前防控**"环节的静态资料部分——识别企业运输经营中的各类风险源，形成手册、清单、岗位告知卡等台账。它与"隐患排查治理"（13 模块，动态记录）**同属一个档案盒，但性质不同**：

- **风险辨识（本模块）**：**静态、事前**——风险点识别与告知，走**系统模板**生成。
- **隐患排查治理（13 模块）**：**动态、事中**——隐患发现与整改，走记录留痕。

**核心定位**：风险辨识**系统提供模板即可**。企业调用模板 → 填充企业/岗位信息 → 生成手册、清单、告知卡、无重大风险说明等 → 一键签名归档。

> 设计逻辑：风险辨识本质是"把风险点写成标准台账"。系统预置模板，企业填的是"自己有哪些风险"，其余格式、结构、签字、盖章全部系统代劳。与应急预案"多套范本"、安全投入"一个数字一张表"一脉相承——**能模板化的绝不手写**。

## 三、核心模型

### 3.1 风险辨识资料清单（R3~R7）

| 归档子项 | 普货 | 危货 | 生成方式 |
|---------|:---:|:---:|---------|
| 风险辨识手册 | ✅ | ✅ | 模板生成 |
| 风险辨识清单 | ✅ | ✅ | 模板生成（勾选风险点） |
| 风险告知卡（每岗位一份） | ✅ | ✅ | 模板生成（按岗位） |
| 无重大风险的说明 | ✅ | ✅ | 模板生成 |
| 安全评估 | ❌ | ✅ | 模板生成（危货专属） |
| 无重大事故隐患的声明 | ❌ | ✅ | 模板生成（危货专属） |

> 隐患相关（隐患排查记录、整改通知书、验收单）由 **13 模块**负责，本模块不涉及。

### 3.2 风险点库模型（R8）

```
系统预置通用风险点库（按运输场景分类）
   ├─ 驾驶员风险（疲劳驾驶/超速/酒驾…）
   ├─ 车辆风险（制动失效/轮胎/灯光…）
   ├─ 货物风险（散落/超载/危化品泄漏…）
   ├─ 环境风险（恶劣天气/路况…）
   └─ 管理风险（制度缺失/培训不到位…）
企业：勾选适用风险点 + 补充自定义风险点
```

> 风险点库是"风险辨识清单"和"风险告知卡"的内容来源，系统预置通用项，企业勾选 + 增补。

## 四、数据模型（DDL）

### 4.1 风险点库表 risk_point_dict（R8）

```sql
CREATE TABLE risk_point_dict (
  id              BIGINT PRIMARY KEY,
  tenant_id       BIGINT NOT NULL DEFAULT 0,    -- 0=系统预置，>0=企业自定义
  risk_name       VARCHAR(200) NOT NULL,        -- 风险点名称（如"疲劳驾驶"）
  risk_category   VARCHAR(50),                  -- 分类：driver驾驶员/vehicle车辆/cargo货物/env环境/manage管理
  risk_level      VARCHAR(20),                  -- 风险等级：红/橙/黄/蓝（重大/较大/一般/低）
  control_measure VARCHAR(1000),                -- 管控措施（模板默认）
  cargo_type      VARCHAR(10),                  -- general普货/danger危货/all通用
  created_at      DATETIME DEFAULT NOW(),
  deleted         TINYINT DEFAULT 0
);
```

### 4.2 风险辨识清单表 risk_list（R4）

```sql
CREATE TABLE risk_list (
  id              BIGINT PRIMARY KEY,
  tenant_id       BIGINT NOT NULL,
  year            INT,                          -- 年度
  risk_point_id   BIGINT,                       -- 风险点（引用字典）
  risk_source     VARCHAR(200),                 -- 风险源（如"恶劣天气/道路条件"，两级清单第二级）
  risk_desc       VARCHAR(500),                 -- 风险描述（企业可补充）
  consequence     VARCHAR(500),                 -- 事故后果（如"人员伤亡、车辆损坏、财产损失"）
  risk_level      VARCHAR(20),                  -- 风险等级
  control_engineering VARCHAR(1000),            -- 风险控制措施·工程技术
  control_manage  VARCHAR(1000),                -- 风险控制措施·管理措施
  responsible_id  BIGINT,                       -- 责任人（组织架构）
  remark          VARCHAR(500),
  created_at      DATETIME DEFAULT NOW(),
  deleted         TINYINT DEFAULT 0
);
```

> 清单 = 企业勾选风险点 + 补充描述/等级/措施/责任人，逐条登记。

### 4.2.1 风险辨识两级清单结构（线下台账比对确认）

> 线下成品把风险辨识清单拆成**两级**，系统生成时对齐此结构：

| 级别 | 线下文件名 | 列结构 | 说明 |
|------|-----------|--------|------|
| **第一级·全面风险辨识清单** | 全面风险辨识清单.xlsx | 辨识项目 / 风险路段·场所·部位 / 作业活动 / 风险描述 / 事故类型 / 备注 | 全量风险点识别，无管控措施 |
| **第二级·安全风险辨识分级管控** | 安全风险辨识分级管控.xlsx | 辨识项目 / 风险路段·场所·部位 / **风险源** / 风险描述 / 事故类型 / **事故后果** / **风险控制措施（工程技术 + 管理措施）** | 在第一级基础上，补风险源、事故后果、控制措施（工程+管理两列） |

> **关键差异**：第二级"分级管控"清单比第一级多 **3 类字段**——`风险源`（如"恶劣天气/道路条件"）、`事故后果`（如"人员伤亡、车辆损坏、财产损失"）、`风险控制措施`（分"工程技术"+"管理措施"两列）。系统数据模型需支持：

- `risk_list` 增加 `risk_source`（风险源）、`consequence`（事故后果）字段
- `control_measure` 拆分为 `control_engineering`（工程技术措施）+ `control_manage`（管理措施）两列

> 据此调整 `risk_list` 表结构：在 4.2 基础上新增 `risk_source`、`consequence` 字段，`control_measure` 拆为工程/管理两列（或保留 `control_measure` 并新增 `control_engineering`）。生成 PDF 时，一级清单输出 6 列，二级清单输出 9 列（含工程/管理措施）。

### 4.3 风险告知卡表 risk_card（R5，每岗位一份）

```sql
CREATE TABLE risk_card (
  id              BIGINT PRIMARY KEY,
  tenant_id       BIGINT NOT NULL,
  year            INT,
  post_id         BIGINT NOT NULL,              -- 岗位（组织架构）
  post_name       VARCHAR(50),                  -- 岗位名（快照）
  risk_points     TEXT,                         -- 该岗位风险点（JSON，引用风险点）
  content_html    LONGTEXT,                     -- 告知卡正文（模板生成）
  created_at      DATETIME DEFAULT NOW(),
  deleted         TINYINT DEFAULT 0
);
```

> 风险告知卡**每个岗位一份**，岗位从组织架构读取，自动关联该岗位相关风险点。

### 4.4 风险辨识手册与说明表 risk_manual（R3/R6/R7）

```sql
CREATE TABLE risk_manual (
  id              BIGINT PRIMARY KEY,
  tenant_id       BIGINT NOT NULL,
  year            INT,
  doc_type        VARCHAR(30),                  -- manual手册/no_risk说明/safety_eval安全评估/no_hidden声明
  doc_name        VARCHAR(200) NOT NULL,
  content_html    LONGTEXT,                     -- 正文（模板生成）
  created_at      DATETIME DEFAULT NOW(),
  deleted         TINYINT DEFAULT 0
);
```

> 手册、无重大风险说明、安全评估、无重大事故隐患声明等，统一走模板生成，存 `doc_type` 区分。

### 4.5 归档映射（R12）

| 归档子项 | 数据来源 |
|---------|---------|
| 风险辨识手册 | `risk_manual`（doc_type=manual） |
| 风险辨识清单 | `risk_list` |
| 风险告知卡（每岗位一份） | `risk_card` |
| 无重大风险的说明 | `risk_manual`（doc_type=no_risk） |
| 安全评估（危货） | `risk_manual`（doc_type=safety_eval） |
| 无重大事故隐患的声明（危货） | `risk_manual`（doc_type=no_hidden） |
| 隐患排查记录/整改/验收 | **13 模块**（`danger_record` 等） |

> 风险辨识的静态项与隐患排查的动态项，最终在归档引擎「盒八/盒九」合并成完整档案盒。归档模板 `TPL_RISK`（08 文档模板清单）。

## 五、核心流程

### 5.1 风险辨识生成流程（R2~R7）

```
① 企业进入风险辨识 → 系统展示预置模板
② 勾选适用风险点（或补充自定义）
③ 模板生成：手册 + 清单 + 岗位告知卡 + 无重大风险说明
   （危货额外：安全评估 + 无重大事故隐患声明）
④ 一键签名（主要负责人 + 安全员，09 文档 8.1）
⑤ 盖公司章 → 归档
```

### 5.2 归档合并流程（R12）

```
① 风险辨识静态项（本模块）+ 隐患排查动态项（13 模块）
② 合并归档到「盒八（普货）/盒九（危货）」
③ 一键生成完整档案盒 PDF
```

## 六、业务规则

1. **只做风险辨识静态项**：隐患排查治理动态项由 13 模块负责（R1）。
2. **系统提供模板**：手册/清单/告知卡/说明全部模板生成，企业不手写（R2）。
3. **风险点库预置**：系统预置通用风险点，企业勾选 + 增补（R8）。
4. **告知卡每岗位一份**：岗位从组织架构读取，自动关联相关风险（R5）。
5. **危货专属两项**：安全评估、无重大事故隐患声明（R7）。
6. **一键签名**：主要负责人 + 安全员一键签名（R9，见 09 文档 8.1）。
7. **盖章**：所有台账自动盖公司章（R10）。
8. **数据可改日志不改**：超管可改风险辨识数据，操作日志不可改（R11）。

## 十一、验收标准

1. 系统预置通用风险点库，企业可勾选 + 增补。
2. 一键生成风险辨识手册、清单、岗位告知卡、无重大风险说明。
3. 风险告知卡每个岗位一份，岗位自动从组织架构读取。
4. 危货企业可生成安全评估、无重大事故隐患声明。
5. 可一键签名（主要负责人 + 安全员）并盖章。
6. 归档可与 13 模块隐患排查动态项合并成完整档案盒 PDF。

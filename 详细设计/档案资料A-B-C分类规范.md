# 档案资料 A/B/C 分类规范（权威单一事实来源）

> 版本：v1.0（定稿）  
> 日期：2026-11-12  
> 定位：本文件是「电子档案柜 / 台账归档 / 范本引擎」全系统归档资料的**唯一权威分类标准**。  
> 适用范围：普货、危货（客运冻结，接入时同样适用）。  
> 上游依据：《产品需求确认文档-道路运输安全生产平台.md》§2.2、《08-台账归档与PDF生成引擎.md》第二章、`server/frontend/src/config/archiveCategory.js`。

---

## 一、为什么是 A/B/C

政府检查目录里的所有资料，按「谁来生产、怎么生产、何时更新」归纳为**三类不可再分**，每一类对应完全不同的系统生产方式。A/B/C 三码是这三类的**代号**，替代原先「①②②′③」四类表述（②′ 上传留存并非独立第四类，见 §四）。

| 代号 | 类型 | 一句话定义 |
|------|------|-----------|
| **A** | 静态资料 | 按范本生成，描述「应该怎么做 / 有什么」，年度更新 |
| **B** | 动态资料 | 企业执行动作后产生的记录，或外部平台台账上传留存，按周期更新 |
| **C** | 证件资料 | 需手动上传，做到期前提醒的证照/凭证 |

## 二、三码权威定义

### A 静态资料（data_type = 1）

- **定义**：根据企业架构、企业信息，按照范本生成；模板可能因**地区 / 企业规模**不同而选用不同的范本套。
- **生产方式**：收集关键信息 → 套用范本 → 人员签字确认 → 生成 PDF 归档。
- **系统角色**：**生成器**（范本/模板引擎）。
- **更新频率**：一般每年度更新；细分见 §五 `renew_freq`（含「一年一签」「变更即更新」「三年修订」等）。
- **模板套差异**：范本套由 `tpl_set` 承载，按 `biz_type`（普货/危货）与地区 `region`、企业规模（通用/小微/规上）选用不同套：
  - 普货通用范本（4001）、普货小微范本（4002）、普货规上范本（4004）、危货通用范本（4003）。
- **典型项**：制度汇编、应急预案、安全生产责任书、承诺书、岗位危害告知书、人员任命书、风险辨识手册/清单、各类计划、成立通知、组织架构、目录清单。

### B 动态资料（data_type = 2）

- **定义**：按照特定的范本，由企业执行对应的动作，完成后归档，一般每月生成；**也可由服务商直接提取企业签字及照片，直接生成归档**。
- **生产方式**（三种，均落到 `gen_mode`）：
  1. **真实流程**（`gen_mode=1`）：企业一线执行（三检/会议/培训/隐患…）→ 系统留痕 → 汇总台账。
  2. **先台账后执行 / 服务商代录**（`gen_mode=2`）：服务商代录或提取签字/照片，直接生成台账。
  3. **外部平台台账上传留存**（`gen_mode=3`）：动态监控台账、在线率/月报等外部平台产出，本系统只上传留存。
- **系统角色**：**记录器 + 留存器**。
- **更新频率**：每月 / 季度 / 每日 / 每趟等周期，细分见 §五。
- **典型项**：会议记录、月度培训、隐患排查、一日三检、事故快报、费用使用台账、动态监控台账、电子运单。

### C 证件资料（data_type = 3）

- **定义**：需要手动上传，**设置到期前 XX 日提醒**。
- **生产方式**：手动上传（拍照/扫描）→ OCR 识别关键字段 + 到期日 → 缺失/到期统一预警 → 换证重传。
- **系统角色**：**看管器**（缺失 + 到期预警）。
- **更新频率**：按证照有效期（`renew_freq=CERT`）。
- **典型项**：营业执照、经营许可证、行驶证、从业资格证、责任险保单、年度营收入证明、备案回执、产权证明、租赁合同、平面图及照片。

## 三、与既有数据模型的映射（代码/数据字典）

| 维度 | 字段 | 取值 | 与 A/B/C 关系 |
|------|------|------|--------------|
| 资料类别 | `archive_item.data_type` | 1 静态 / 2 动态 / 3 证件 | **A/B/C 的直接落点** |
| 生成方式 | `archive_item.gen_mode` | 1 真实流程 / 2 先台账后执行 / 3 上传留存 | B 内部的三种生产方式；A 固定为范本生成，C 固定为上传 |
| 归档来源 | `archive_item.source` | 0 未知 / 1 手动上传 / 2 B3 流程 / 3 服务商强制生成 | 独立维度，记录「谁产生、从哪来」，与 A/B/C 正交 |
| 更新频率 | `archive_catalog.renew_freq` | 见 §五 | A/B/C 之下的**二级维度**，驱动重签/到期预警 |

> **关键**：A/B/C（`data_type`）决定「怎么生产」，`renew_freq` 决定「何时重做/到期」，`source` 决定「谁产生、从哪来」。三者**正交**，不可混为一谈。

前端渲染字典：`server/frontend/src/config/archiveCategory.js` 的 `CATEGORY` 已改为 A/B/C 三码（`code` 字段），`ITEM_CATEGORY` 显式表逐项标注，`categoryOf()` 关键词兜底仅用于后端动态追加项。

## 四、原「②′ 上传留存」的拆分（本次定稿）

原四类中的「②′ 上传留存」是 `data_type=2` 下的一个子型，内部实为两类性质不同的东西，本次**拆分归入 B / C**：

| 原 ②′ 子项 | 归类 | 理由 |
|-----------|------|------|
| 动态监控工作情况记录台账（每日）、设备故障异常台账、在线率台账、月报台账 | **B（动态）** | 外部平台产出的台账/记录，非证件，无「证照到期」概念 |
| 应急预案备案回执、产权证明、租赁合同、平面图及照片 | **C（证件）** | 证照/凭证性质，需做到期预警 |

前端「上传留存」生产方式提示（`src-up` 徽标）**保留**，作为 B 动态资料下的子型标识，与类别徽标（A/B/C）相互独立。

## 五、更新频率（renew_freq 二级维度，权威枚举）

> 枚举沿用《08-台账归档与PDF生成引擎.md》§2.1.1，作为 A/B/C 之下的二级维度，驱动预警引擎。

| renew_freq | 含义 | 典型项 |
|-----------|------|--------|
| `YEARLY` | 每年更新（含「一年一签」重签 与「年度一次」重新生成） | 责任书、承诺书、培训计划、风险辨识清单、年度考核 |
| `ONCE` | 入职一次 | 岗前三级培训、岗位危害告知书 |
| `MONTHLY` | 每月 | 月度培训、月度会议、隐患排查、费用使用台账、在线率/月报台账 |
| `QUARTERLY` | 每季度 | 安全生产领导小组会议 |
| `DAILY` | 每日 | 一日三检、动态监控每日台账、危险品运输台账 |
| `TRIP` | 每趟 | 危货电子运单、装卸查验、押运员在岗、800 公里线路台账 |
| `CERT` | 按证照有效期 | 营业执照、许可证、责任险、备案回执、租赁合同 |
| `ONCHANGE` | 有变动时更新 | 组织架构、任命书、领导小组通知、制度汇编、风险告知卡、应急预案评审 |
| `LONG` | 长期（法定周期/三年修订） | 应急预案、风险评估与应急资源调查、安全评估（危货）、产权证明 |

> **一年一签 vs 年度一次的区分**：两者 `renew_freq` 均为 `YEARLY`，但「一年一签」类（责任书/承诺书）额外由 `archive_item.signed_year` 判定——**签署年度 < 当前自然年度即跨年需重签**（按自然年度，不按「签署日+365 天」）；服务商代录复用历史签字时，对 `YEARLY` 文件校验签字年份，跨年提示重签。

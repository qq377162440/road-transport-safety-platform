# 详细设计 07 —— 人员基础信息 + 一人一档

> 所属域：archive（人员档案）
> 设计基准：**档案盒标签《一人一档》目录**（普货/危货，见 `/root/uploads/*/档案盒标签250318.docx`，已逐字对齐到 08 归档引擎 2.3 节）
> 上游依赖：03 企业信息管理、06 组织架构（岗位）、09 范本引擎（责任书/承诺书/告知书生成）
> 下游被依赖：11 一日三检、预警引擎（证照到期）、08 台账归档（一人一档归档单元已定义）

## 一、模块定位

人员是平台**第一类核心主数据**。本模块目标：**让每名从业人员最终能自动产出档案盒《一人一档》要求的全部归档材料**。

> 关键认知（本次修正）：逆向报告的"原系统实测文档编码全集（17 种）"是**录入层**，档案盒标签的"一人一档目录（普货 12 项 / 危货 13 项）"才是**归档交付层**。设计以归档目录为骨架，逐项回答"由哪些录入字段 / 哪个模块自动生成"。

**边界**：本模块管理"人员基础信息 + 一人一档归档项"。其中**安全生产责任书、承诺书、岗位危害告知书、岗前三级培训**等归档项由范本引擎（09）与培训模块生成，本模块只声明它们向"一人一档"贡献归档项并做完整度校验。

## 二、一人一档归档目录（设计总骨架，以档案盒标签为准）

### 2.1 归档目录（普货 / 危货逐字对照）

| # | 归档项 | 普货 | 危货 | 数据来源 | 归档形态 |
|---|--------|------|------|---------|---------|
| 1 | 驾驶员基础信息登记表 | ✅ | ✅ | 本模块：`person` 汇总生成 | 自动生成 PDF |
| 2 | 驾驶证 | ✅ | ✅ | 本模块：`person_doc` | 上传扫描件 |
| 3 | 从业资格证 | ✅ | ✅ | 本模块：`person_doc` | 上传扫描件 |
| 4 | 劳动合同 | ✅ | ✅ | 本模块：`person_doc` | 上传扫描件 |
| 5 | 体检报告（如有）/ 职业健康检查报告 | ✅（如有） | ✅（强制） | 本模块：`person_doc` | 上传扫描件 |
| 6 | 岗前三级教育培训 | ✅ | ✅ | 培训模块（逆向 2.22 岗前教育） | 动态台账 |
| 7 | 安全生产责任书 | ✅ | ✅ | 范本引擎（09）生成 | 自动生成 PDF |
| 8 | 安全生产承诺书 | ✅ | ✅ | 范本引擎（09）生成 | 自动生成 PDF |
| 9 | 岗位职业病危害因素告知书 | ✅ | ✅ | 范本引擎（09）生成 | 自动生成 PDF |
| 10 | 禁毒承诺书 | — | ✅（独有） | 范本引擎（09）生成 | 自动生成 PDF |
| 11 | 年度责任制考核记录 | ✅ | ✅ | 考核奖惩模块（逆向 3.7） | 动态台账 |
| 12 | 历史记录登记表（诚信考核记录、违章记录、奖惩记录） | ✅ | ✅ | 诚信考核模块（逆向 3.8）聚合 | 自动汇总 PDF |

> **普货 vs 危货差异**（两处）：① 危货多"禁毒承诺书"一项；② 第 5 项体检报告在危货下升级为"职业健康检查报告"（入职 + 年度在岗，**强制**）。其余 11 项完全相同。

### 2.2 归档项产出方式（核心原则：每一项目录最终都必须"有实物"）

> **总原则（用户确认）**：档案盒里每项目录最终都要有实物装盒、能过政府检查。实物产生方式只有三种，且**登记表/记录表类优先自动生成，无数据则打印空白表手写补充**：
>
> | 产出方式 | 含义 | 系统动作 |
> |---------|------|---------|
> | **① 系统生成** | 系统里有数据 → 直接产出最终 PDF | 自动 |
> | **② 企业自备** | 证件等实物 → 企业扫描上传 | 上传 |
> | **③ 打印手写** | 系统里**没有数据** → 打印**空白表头/格式**，提示企业手写补充 | 打印空白模板 |

**13 项归档材料的产出方式分配**：

| 类别 | 归档项 | 产出方式 |
|------|--------|---------|
| ① 系统生成（有数据） | 1 登记表、12 历史记录 | 结构化数据**自动生成 PDF** |
| ② 范本生成 | 7 责任书、8 承诺书、9 告知书、10 禁毒承诺书 | 范本引擎（09）自动生成 |
| ③ 企业自备 | 2 驾驶证、3 从业资格证、4 劳动合同、5 体检报告 | 上传扫描件（OCR 回填），证件类无"手写"选项 |
| ④ 系统生成（有数据）/ 打印手写（无数据） | 6 岗前培训、11 年度考核 | 培训/考核模块有记录→汇总生成；无记录→打印空白表手写 |

> **降级规则（贯穿全模块）**：凡"登记表/记录表"类归档项（1/6/11/12），系统先查对应模块有无数据——**有数据→生成成品 PDF；无数据→打印空白格式表，提示"该表无系统数据，请打印后手写补充"**。证件类（③）不适用降级，必须上传实物。

## 三、人员基础信息（主数据）

**列表列**（沿用原系统实测）：人员姓名、政治面貌、性别、部门、岗位、手机号、头像、**小程序账号状态（已开通 · 手机号登录）**、创建时间、操作

**筛选**：手机号、姓名、部门、岗位、政治面貌

**表单字段**：

| 字段 | 必填 | 说明 |
|------|------|------|
| 姓名 | ✅ | |
| 手机号 | ✅ | 关联账号/提醒 |
| 岗位 | ✅ | 关联组织架构 org_post |
| 性别 | | |
| 部门 | | |
| 政治面貌 | | 13 类枚举 |
| 头像 | | 图片上传 |
| 身份证号 | | |
| 人员类型 | ✅ | 管理人员 / 从业人员 |

> **简化说明**：原系统区分"管理人员档案 / 从业人员档案"两套菜单，但档案盒标签的"一人一档"目录**只针对从业人员（驾驶员/押运员）**。管理人员（主要负责人/安全管理人员）属于"公司档案及管理层档案"盒（盒一），不在"一人一档"归档单元内。因此本模块的"一人一档"归档单元**仅面向从业人员**；管理人员的文档清单沿用原系统，但不参与"一人一档"完整度校验。

> **管理人员档案 + 两类人员考核合格证明（盒一子项，本模块负责）**：盒一"公司档案及管理层档案"里的两个子项——**管理人员档案**（主要负责人/安全员/监控员等管理岗的证照、任命、责任书等，由 09 范本引擎生成 + 证照上传聚合）和**两类人员考核合格证明**（主要负责人 + 安全员参加主管部门安全考核的合格证明，属**外部证件，企业自备上传**，走 `person_doc` 证照子表，cert_type 增加"两类人员考核合格证明"）——均由本模块登记管理，归档到盒一。

## 四、数据模型（DDL）

### 4.1 人员主表 person

```sql
CREATE TABLE person (
  id           BIGINT PRIMARY KEY,            -- 雪花ID
  tenant_id    BIGINT NOT NULL,
  person_type  VARCHAR(20) NOT NULL,          -- manager=管理人员 / employee=从业人员
  name         VARCHAR(50) NOT NULL,
  telephone    VARCHAR(20) NOT NULL,
  gender       TINYINT,                       -- 1男 0女
  politic      VARCHAR(20),                   -- 政治面貌（13类枚举）
  id_card      VARCHAR(18),                   -- 身份证号
  avatar       VARCHAR(200),                  -- 头像
  dept_id      BIGINT,                        -- 部门（org_dept）
  post_ids     VARCHAR(500),                  -- 岗位（多选，org_post.id 逗号分隔）
  created_at   DATETIME DEFAULT NOW(),
  updated_at   DATETIME,
  deleted      TINYINT DEFAULT 0
);
```

### 4.2 人员文档子表 person_doc（对应归档项 2/3/4/5 的证件类）

```sql
CREATE TABLE person_doc (
  id           BIGINT PRIMARY KEY,
  tenant_id    BIGINT NOT NULL,
  person_id    BIGINT NOT NULL,               -- 关联 person
  doc_code     VARCHAR(30) NOT NULL,          -- 文档编码（见 4.4，逐一对齐目录）
  doc_name     VARCHAR(100),                  -- 文档名称（冗余）
  file_url     VARCHAR(500),                  -- 扫描件（对象存储）
  issue_date   DATE,                          -- 发证/签订日期
  expire_date  DATE,                          -- 有效期至（→预警）
  status       TINYINT DEFAULT 0,             -- 0未上传 1已上传 2已过期
  created_at   DATETIME DEFAULT NOW(),
  updated_at   DATETIME
);
```

### 4.3 一人一档归档项登记表 person_archive_item（完整度校验载体）

> 类比 `vehicle_doc` 的思路，但这里记录的是**归档项**（含范本生成类、动态台账类），不限于上传的证件。

```sql
CREATE TABLE person_archive_item (
  id            BIGINT PRIMARY KEY,
  tenant_id     BIGINT NOT NULL,
  person_id     BIGINT NOT NULL,
  item_code     VARCHAR(30) NOT NULL,         -- 归档项编码（见 4.4，13项目录）
  source_type   VARCHAR(20),                  -- upload上传/auto系统生成/print打印手写
  ref_id        BIGINT,                       -- 关联源数据（如范本生成PDF id / 培训记录id）
  file_url      VARCHAR(500),                 -- 成品PDF或扫描件
  expire_date   DATE,
  status        TINYINT DEFAULT 0,            -- 0缺 1齐 2已过期
  created_at    DATETIME DEFAULT NOW()
);
```

### 4.4 一人一档归档项目录字典 person_archive_dict（逐字对齐 2.1 表）

```sql
CREATE TABLE person_archive_dict (
  id           BIGINT PRIMARY KEY,
  item_code    VARCHAR(30) NOT NULL UNIQUE,
  item_name    VARCHAR(100) NOT NULL,         -- 归档项名称（逐字对齐档案盒目录）
  source_type  VARCHAR(20) NOT NULL,          -- upload上传/auto系统生成/print打印手写
  apply_biz    VARCHAR(50),                   -- 适用营运类型：freight/danger/passenger
  is_optional  TINYINT DEFAULT 0,             -- 是否可选（体检报告=普货可选/危货强制）
  sort_no      INT DEFAULT 0
);
```

## 五、归档完整性校验（一人一档的核心价值）

### 5.1 校验规则

| 归档项 | 齐全判定 |
|--------|---------|
| 1 登记表 | `person` 必填字段齐全 |
| 2 驾驶证 | `person_doc` 存在且未过期 |
| 3 从业资格证 | `person_doc` 存在且未过期 |
| 4 劳动合同 | `person_doc` 存在且未过期 |
| 5 体检报告 / 职业健康检查报告 | 普货可选（有则校验有效期）；**危货强制**（入职+年度在岗职业健康检查） |
| 6 岗前培训 | 培训模块有岗前三级培训记录 |
| 7/8/9/10 责任书/承诺书/告知书/禁毒 | 范本引擎已生成对应 PDF（危货额外校验禁毒承诺书） |
| 11 年度考核 | 考核模块有年度责任制考核记录 |
| 12 历史记录 | 诚信考核模块有记录 |

### 5.2 输出

- 每人一个**归档完整度百分比** + 缺项清单
- 列表页增加"归档完整度"列
- 危货自动启用"禁毒承诺书"校验，普货不校验

## 六、页面交互设计（PC 端）

### 6.1 人员列表页

- 列表列：姓名、岗位、部门、手机号、政治面貌、**归档完整度**、操作

### 6.2 人员档案详情页（一人一档视角，核心）

**以 13 项归档目录为骨架的卡片列表**，每项显示：

- 归档项名称 + 是否齐全（✓/✗）
- 生成/上传入口
- 有效期状态

分组呈现（四类）：
- **静态生成区**：1 登记表、12 历史记录 → 一键生成 PDF；若无系统数据，则提供"打印空白表"按钮供手写

- **范本生成区**：7/8/9/10 → 跳转范本引擎生成（09）
- **动态台账区**：6 岗前培训、11 年度考核 → 有记录汇总生成，无记录打印空白表手写

### 6.3 与智能资料收集联动

- 批量上传驾驶证/从业资格证 → OCR 回填并自动登记到对应归档项

## 八、业务规则

1. **归档完整度实时计算**：任一项齐全状态变化，实时重算。
2. **证照到期预警**：`person_doc.expire_date` 接入统一预警引擎（30/15/7 天）。
3. **危货差异自动加载**：`biz_type=danger` 自动启用"禁毒承诺书"校验。
4. **体检报告**：普货可选（不影响完整度分母，有则校验有效期）；**危货强制**（职业健康检查报告，入职 + 年度在岗）。
5. **软删除**：`deleted=1`，历史归档项仍可关联回查。
6. **登记表类降级（有数据生成/无数据手写）**：凡登记表/记录表类归档项（1/6/11/12），系统先查有无对应业务数据——有则生成成品 PDF，无则打印空白表头并提示"无系统数据，请打印手写补充"。证件类不适用降级。
7. **小程序端账号自动开通（录入即开通）**：
   - 录入人员信息（姓名 / **手机号** / 岗位）时，**所有岗位自动开通**小程序端账号，无需单独建号。
   - 小程序登录账号 = **人员手机号**，初始密码 = **123456**。
   - 不同岗位按自身职责显示不同功能（驾驶员/押运员侧重一日三检、报修、报隐患、签文件、学习中心；安全员/安全管理人员侧重督办隐患、证件到期提醒、三检统计、下发任务、安全数据；企业管理员可见全部管理功能 + 驾驶舱），权限与 PC 端组织权限同源。
   - 人员离职 / 停用 → 小程序账号**同步停用**；人档车档保留 ≥ 3 年，启用后账号恢复。

## 九、开发任务拆解

1. 建表（person / person_doc / person_archive_item / person_archive_dict）
2. 人员 CRUD + 列表（含归档完整度列）
3. 证件上传 + OCR 回填 + 自动落归档项
4. 归档完整度实时计算引擎
5. 静态类归档 PDF 生成（登记表/历史记录）
6. 空白表打印（登记表类归档项无数据时，打印表头格式供手写）
7. 范本类归档项（责任书/承诺书/告知书/禁毒）→ 范本引擎联动（09）
8. 证照到期 → 预警引擎接入（02）
9. 一人一档归档项 → 08 归档引擎登记

## 十、验收标准

1. 能完整录入一名从业人员并自动生成 13 项归档目录的完整性视图。
2. 每人能实时显示"归档完整度百分比 + 缺项清单"。
3. 危货人员自动启用"禁毒承诺书"校验，普货不启用。
4. 静态类归档项（登记表/历史记录）能一键生成 PDF。
5. 责任书/承诺书/告知书/禁毒承诺书能由范本引擎自动生成并登记。
6. 证照任一到期，预警引擎按 30/15/7 天分级触发。
7. 人员软删除后，历史归档项仍能关联回查。

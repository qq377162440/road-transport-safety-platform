> 所属域：credit（考核奖惩 + 诚信）
> 优先级：**P1 刚需**（需求文档二期；档案盒「盒一·公司档案及管理层档案」的"年度责任制考核记录" + 一人一档的"年度责任制考核记录、诚信考核记录、违章记录、奖惩记录"）

> 上游依赖：01 组织权限、06 组织架构（岗位 + 人员）、09 范本引擎（岗位目标指标 + 一键签名）、14 培训教育（违规类型字典 + 靶向培训）

## 一、模块定位

考核奖惩是"**履职评价**"环节——企业每年对每个岗位的安全生产责任目标完成情况进行考核，形成年度责任制考核记录。这是政府检查"责任制落实"的直接证据。

**核心定位**：
- **主要做责任制考核**，一年一次。
- **按岗位责任目标设置**（责任目标来自 09 文档"岗位目标指标"，即岗位内容库 `target`）。
- **每个岗位默认 100 分**，方便**一键提交、一键签名、一键生成**。
- **驾驶员可联动靶向教育的违规情况，酌情减分**（联动 14 培训教育的违规类型）。

> 设计逻辑：责任制考核 = **岗位目标（09 已有）+ 默认满分 + 一键流转 + 违规减分（联动14）**。系统把"考核什么、打多少分、怎么签字"全部预置好，企业绝大多数情况"一键过"，只有驾驶员有违规时才需要酌情减分。

## 三、核心模型

### 3.1 责任制考核模型（C1~C6）

```
年度考核（一年一次）
   ├─ 按岗位取责任目标（09 岗位内容库 target）
   ├─ 每岗位默认 100 分
   ├─ 驾驶员：联动靶向教育违规情况 → 酌情减分
   ├─ 一键提交 → 一键签名 → 一键生成台账
   └─ 考核结果 → 沉淀到一人一档（诚信/奖惩记录）
```

### 3.2 考核评分规则（C4/C6/C8）

| 项目 | 规则 |
|------|------|
| 默认分值 | 100 分（满分） |
| 违规减分 | 驾驶员有靶向教育违规记录时，酌情减分（每类违规可配减分幅度） |
| 等级划分 | 90 分以上=优秀；60~89=合格；60 分以下=不合格 |
| 减分方式 | 系统**自动提示**该驾驶员本年违规情况，安全员**手动确认减分幅度**（不自动扣，避免误伤） |

> **减分设计原则**：系统"提示"违规情况，人"决定"减多少分——避免自动扣分误判，保留企业裁量权（对应"酌情减分"）。

## 三、台账字段对齐（两类台账与政府检查台账样例一一对应）

> 考核奖惩产出**两类台账**，字段与线下「安全生产责任制考核记录」「安全生产考核奖惩公示」台账样例逐字段对应。

### 3.3 台账一：安全生产责任制考核记录（归档「从业人员考核记录」）

| 台账字段 | 系统来源 | 说明 |
|---------|---------|------|
| 被考核人 | `credit_assess_item.user_id` | 按人一条 |
| 考核事项 | 岗位内容库 `target` 分类（安全教育培训/安全会议管理/应急管理/责任事故管理等） | 台账行首分组列 |
| 考核内容 | `target` 的目标描述（如"组织、参与本公司安全生产教育和培训，如实记录…"） | 每事项下的逐条要求 |
| 考核标准 | `target` 的扣分标准（如"未如实记录…扣2分/项"） | 台账"考核标准"列 |
| 评分标准 | 扣分幅度（扣2分/项、扣5分/项、扣10分/项） | 台账"评分标准"列 |
| 应得分 | `target` 预设分值（4/2/5/10…） | 台账"应得分"列 |
| 实得分 | `score`（默认 100，减分后 = 应得 − deduction） | 台账"实得分"列 |
| 考核结论/签字 | `level` + `sign_image`（被考核人签字）+ 考核人签字 | 结论"合格/不合格" |
| 考核周期 | `year`（一年一次） | 台账表头 |

### 3.4 台账二：安全生产考核奖惩公示（归档「从业人员奖惩公示」）

| 台账字段 | 系统来源 | 说明 |
|---------|---------|------|
| 公告编号 | 自动生成（如 `XTTA 公告【2026】xxx 号`） | 台账右上角 |
| 考核类型 | 安全生产责任制考核（`assess_name`） | 台账"考核类型" |
| 考核周期 | `year`（起止日期） | 台账"考核周期" |
| 考核结果 | `level`（合格/优秀/不合格） | 台账"考核结果" |
| 被考核对象 | `post_name`（分管安全负责人/安全管理员/驾驶员…） | 台账"被考核对象" |
| 被考核人 | `user_id` 姓名 | 台账"被考核人" |
| 考核标准 | 达成指标的描述 | 台账"考核标准" |
| 评定条件 | 评优条件（如"考核结果为优秀"） | 台账"评定条件" |
| 奖惩详情 | 奖惩措施（记功·公开表扬 / 减分 / 通报…） | 台账"奖惩详情" |
| 签字/备注/时间 | 考核人签字 + 被考核人签字 + 备注 + 公示时间 | 台账底部 |

> **归属变化说明**：原设计将考核记录归档到「盒一·年度责任制考核记录」；按台账样例"考核记录/奖惩公示"为**从业人员维度**的月度/周期考核，现下沉到**盒十一·一人一档/一车一档**，新增归档项「从业人员考核记录」「从业人员奖惩公示」，与一人一档的"考核/诚信/奖惩记录"沉淀打通。盒一仍保留"年度责任制考核记录"（管理层维度）。

## 四、数据模型（DDL）

### 4.1 年度考核主表 credit_assess（C1/C2/C4）

```sql
CREATE TABLE credit_assess (
  id              BIGINT PRIMARY KEY,
  tenant_id       BIGINT NOT NULL,
  year            INT NOT NULL,                 -- 考核年度
  assess_name     VARCHAR(200) NOT NULL,        -- 如"2026年度安全生产责任制考核"
  status          VARCHAR(20) DEFAULT 'draft',  -- draft/confirming/completed
  created_by      BIGINT,
  created_at      DATETIME DEFAULT NOW(),
  updated_at      DATETIME,
  deleted         TINYINT DEFAULT 0
);
```

### 4.2 考核明细表 credit_assess_item（C2/C3/C4/C6/C8）

```sql
CREATE TABLE credit_assess_item (
  id              BIGINT PRIMARY KEY,
  tenant_id       BIGINT NOT NULL,
  assess_id       BIGINT NOT NULL,              -- 关联年度考核
  user_id         BIGINT NOT NULL,              -- 被考核人
  post_id         BIGINT,                       -- 岗位（组织架构）
  post_name       VARCHAR(50),                  -- 岗位名（快照）
  targets         TEXT,                         -- 责任目标快照（JSON，来自岗位内容库 target）
  score           INT DEFAULT 100,              -- 得分（默认100，C4）
  deduction       INT DEFAULT 0,                -- 减分（违规联动，C6）
  deduction_note  VARCHAR(500),                 -- 减分说明（违规类型/情况）
  level           VARCHAR(20),                  -- 等级：excellent优秀/pass合格/fail不合格（C8）
  sign_image      VARCHAR(500),                 -- 被考核人签名
  sign_time       DATETIME,
  created_at      DATETIME DEFAULT NOW(),
  updated_at      DATETIME
);
```

> 考核明细**按人一条**，`score` 默认 100；`deduction` 由安全员在系统提示下确认；`targets` 为考核时岗位目标的快照（留痕）。

### 4.3 违规减分来源（C7，联动 14 培训教育）

> 复用 14 培训教育的 `violation_dict`（违规类型字典）+ `training_plan`（靶向培训）+ `training_assign`（培训人员）。考核时：

```
驾驶员被考核 → 系统查询该驾驶员本年靶向培训记录（training_plan.plan_type='targeted'）
            → 提取违规类型（violation_dict）
            → 提示安全员"该驾驶员本年有 N 类违规：疲劳驾驶、超速…"
            → 安全员确认减分幅度 → 写入 deduction + deduction_note
```

### 4.4 归档映射（C9/C12）

| 归档位置 | 归档子项 | 数据来源 |
|---------|---------|---------|
| 盒一·公司档案及管理层档案 | 年度责任制考核记录 | `credit_assess` + `credit_assess_item` |
| 一人一档 | 年度责任制考核记录 | `credit_assess_item`（按人） |
| 一人一档 | 诚信考核记录 | `credit_assess_item`（等级沉淀） |
| 一人一档 | 违章记录 | 联动 14 违规类型（violation_dict） |
| 一人一档 | 奖惩记录 | 考核结果（奖惩建议） |

> 考核结果**自动沉淀**到一人一档（07），形成"诚信考核记录、违章记录、奖惩记录"。归档模板 `TPL_CREDIT`（08 文档模板清单）。

## 五、核心流程

### 5.1 责任制考核流程（C1~C6）

```
① 创建年度考核（一年一次）
② 系统按组织架构自动生成所有岗位的考核明细，默认 100 分
③ 驾驶员：系统联动靶向教育违规情况 → 提示 → 安全员酌情减分
④ 一键提交（全岗位默认满分直接过）
⑤ 一键签名（主要负责人 + 安全员，09 文档 8.1）
⑥ 一键生成考核台账（带盖章）→ 归档 + 沉淀一人一档
```

## 六、业务规则

1. **一年一次责任制考核**，按岗位生成（C1/C2）。
2. **目标来自岗位内容库**：考核依据 = 09 决策 C 的岗位目标指标 `target`（C3）。
3. **默认 100 分**：满分即达标，一键提交（C4）。
4. **一键流转**：提交 + 签名 + 生成台账一键完成（C5）。
5. **违规减分联动**：驾驶员联动靶向教育违规情况，系统提示、人工酌情减分（C6/C7）。
6. **减分不自动扣**：系统提示违规、人确认减分幅度，保留裁量权（C6）。
7. **等级划分**：90 分优秀 / 60 分合格 / 以下不合格（C8）。
8. **结果沉淀一人一档**：诚信/违章/奖惩记录自动写入（C12）。
9. **盖章**：考核记录自动盖公司章（C10）。
10. **数据可改日志不改**：超管可改考核数据，操作日志不可改（C11）。

## 十一、验收标准

1. 创建年度考核后，系统按岗位自动生成明细，默认 100 分。
2. 考核依据来自岗位责任目标（岗位内容库 target）。
3. 驾驶员可联动靶向教育违规情况，系统提示、酌情减分。
4. 一键提交、一键签名、一键生成台账。
5. 考核结果（得分/等级/奖惩）自动沉淀到一人一档。
6. 归档可生成盒一「年度责任制考核记录」+ 一人一档考核/诚信/奖惩记录 PDF（带盖章）。

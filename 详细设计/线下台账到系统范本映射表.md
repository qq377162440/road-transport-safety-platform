# 线下台账 → 系统范本 逐文件映射表

> 目的：把用户上传的《台账合集.zip》（82 个线下文件）逐文件映射到系统模块、范本、生成方式、变量来源，形成"线下有什么 → 系统怎么生成"的**全局唯一准绳**。
>
> 配套文档：
> - 《线下台账合集比对分析报告.md》——差异点与修正建议（4 处）
> - 08《台账归档与PDF生成引擎.md》——档案盒目录 + 归档模型
> - 09《静态资料范本引擎.md》——变量化机制 + 字段字典 + 一键签名

## 〇、映射总览（先看结论）

| 生成方式 | 代号 | 说明 | 线下文件占比 |
|---|---|---|---|
| **① 静态范本生成** | `T`（Template） | 制度/预案/责任书等，范本引擎填充变量 → PDF | 约 60%（盒一、二、五计提计划、七预案） |
| **② 动态执行采集** | `D`（Dynamic） | 业务模块执行时采集（会议/培训/隐患/三检/监控）→ 汇总 PDF | 约 30%（盒三、四、六、八、九） |
| **③ 证件上传留存** | `C`（Cert） | 企业证照/发票/照片，上传 + OCR + 到期预警 | 约 10%（营业执照、许可证、发票、照片） |

> 三种方式正好对应 08 文档"三类资料"（①静态 / ②动态 / ③证件）。**线下台账的每一个文件，都能落到这三种方式之一。**

**档案盒归属（普货基准）**：线下是普货企业，12 盒结构（09/10/12 为空）。映射表以**普货 10 盒 + 一人一档 + 一车一档**为基准；危货多"停车场管理"盒导致盒号顺延，但**归档项 `code` 不变**（铁律：业务模块绑 code 不绑盒号）。

> 所属域：meeting（安全会议管理）
> 优先级：**P0 保命功能**（法规强制"安全生产会议"制度，直接对应"证明我管了"）
> 对应原系统：archive 子系统「安全会议管理」（逆向报告 3.4）

> 下游被依赖：08 归档引擎（盒三·安全生产会议）、企业安全分（会议完成率）、小程序首页（今日三步·会议签到）

## 一、模块定位

安全会议是"**日常执行**"环节的核心之一（需求文档因果链：风险辨识 → 制度固化 → 人员/车辆合规 → **日常执行** → 隐患闭环 → 事故兜底）。它是法规强制要求的安全管理动作——**不开会、不签到、不留痕，就是"没管"**。

**核心目标**：把"开会"从一件线下走形式的事，变成**线上闭环留痕**的动作——开会前有通知、开会时能签到、开会后有纪要、归档时能一键出盒。

**双端分工**（沿用全系统范式）：

| 端 | 角色 | 职责 |
|----|------|------|
| PC 管理端 | 安全员/管理员 | 创建会议、发布通知、录入纪要、上传 PPT/照片、汇总台账、一键归档 |
| 小程序 | 司机/参会人 | **30 秒签到**（会议签到是"今日三步"第 2 步）+ 查看会议通知 |

**边界**：
- 本模块只做"**会议的组织 + 留痕 + 归档**"。会议的**内容**（议题讨论、决议）由会议记录富文本承载，不做在线协同、**不做内建音视频会议**（线上会议复用腾讯会议，跳转即可）。
- **培训**（教育培训）是独立模块（后续单独设计），与会议区分：会议=议事/宣贯，培训=教学/考核。二者在档案盒里分属盒三、盒四。

## 三、核心模型

### 3.1 会议类型（M1，对齐档案盒）

> **关键洞察**：档案盒「盒三·安全生产会议」只有**两个子项**——安全生产领导小组会议、安全生产月度会议。原系统原型里的"安全例会/专题会议/应急演练"是泛化口径，**本系统以档案盒目录为准**，会议类型收敛为两类。

| 会议类型 | 编码 | 频次 | 归档子项 | 说明 |
|---------|------|------|---------|------|
| 安全生产领导小组会议 | leader | 定期（季度/半年，可配） | 盒三·安全生产领导小组会议 | 由安全生产领导小组召开，议事决策 |
| 安全生产月度会议 | monthly | 每月 | 盒三·安全生产月度会议 | 月度安全例会，宣贯/总结/部署 |

> 两类会议**归档口径一致**：会议记录 + 会议PPT + 签到 + 照片。区别仅在归档子项归属不同。

### 3.2 会议生命周期状态机

```
草稿 → 已发布(未开始) → 进行中 → 已结束 → 已归档
              ↓                    ↓
           取消/作废           补录纪要
```

| 状态 | 含义 | 触发 |
|------|------|------|
| `draft` 草稿 | 已创建未发布 | 创建保存 |
| `published` 未开始 | 已发布通知，会议未到时间 | 发布通知 |
| `ongoing` 进行中 | 会议开始，开放签到 | 到达开始时间 |
| `finished` 已结束 | 会议结束，待录纪要 | 到达结束时间 |
| `archived` 已归档 | 纪要/签到/照片齐备，已登记归档 | 一键归档到 08 |

### 3.3 签到状态（M3/M9）

| 状态 | 含义 | 触发 |
|------|------|------|
| `signed` 已签到 | 签名图片 + 时间戳已记录 | 现场签到 / 补签 |
| `absent` 缺席 | 未签到 | 会议结束后未签 |
| `leave` 请假 | 缺席原因=请假 | 安全员标记 |
| `补签` | 会后补签（来源标记） | 安全员/超管补签 |

## 四、数据模型（DDL）

### 4.1 会议主表 meeting

```sql
CREATE TABLE meeting (
  id              BIGINT PRIMARY KEY,
  tenant_id       BIGINT NOT NULL,
  meeting_type    VARCHAR(20) NOT NULL,        -- leader领导小组会议 / monthly月度会议（见 3.1）
  title           VARCHAR(200) NOT NULL,       -- 会议名称（如"2026年10月安全生产月度会议"）
  topic           VARCHAR(1000),               -- 会议议题
  mode            VARCHAR(10) DEFAULT 'offline', -- online线上 / offline线下
  meeting_no      VARCHAR(50),                 -- 腾讯会议号（mode=online，如"123 456 789"）
  link            VARCHAR(500),                -- 会议链接（mode=online，腾讯会议/企微等，通用字段不锁厂商）
  location        VARCHAR(200),                -- 会议地点（mode=offline）
  start_time      DATETIME NOT NULL,           -- 开始时间
  end_time        DATETIME NOT NULL,           -- 结束时间
  host_id         BIGINT NOT NULL,             -- 主持人
  recorder_id     BIGINT NOT NULL,             -- 记录人
  attach_files    VARCHAR(2000),               -- 会议附件（JSON）
  notice_title    VARCHAR(200),                -- 通知标题（模板占位）
  notice_content  TEXT,                        -- 通知内容
  status          VARCHAR(20) DEFAULT 'draft', -- draft/published/ongoing/finished/archived
  created_at      DATETIME DEFAULT NOW(),
  updated_at      DATETIME,
  deleted         TINYINT DEFAULT 0
);
```

### 4.2 参会人员表 meeting_attendee（签到）

```sql
CREATE TABLE meeting_attendee (
  id              BIGINT PRIMARY KEY,
  tenant_id       BIGINT NOT NULL,
  meeting_id      BIGINT NOT NULL,
  user_id         BIGINT NOT NULL,             -- 参会人（从业人员）
  sign_image      VARCHAR(500),                -- 签名图片（关键留痕）
  sign_time       DATETIME,                    -- 签到时间戳（自动）
  sign_status     VARCHAR(10) DEFAULT 'absent', -- signed已签到/absent缺席/leave请假
  absent_reason   VARCHAR(200),                -- 缺席原因
  sign_source     VARCHAR(10) DEFAULT 'self',  -- self现场签到/replenish补签（M9）
  replenished_by  BIGINT,                      -- 补签操作人（安全员/超管）
  created_at      DATETIME DEFAULT NOW()
);
```

> **签到 = 关键操作留痕（M3）**：`sign_image`（签名图片）+ `sign_time`（自动时间戳）+ `sign_status`，一旦生成不可由用户随意修改（5.3 留痕原则）。补签（M9）也必须标记 `sign_source=replenish` + `replenished_by`，留痕可追溯。

### 4.3 会议记录表 meeting_record（纪要）

```sql
CREATE TABLE meeting_record (
  id              BIGINT PRIMARY KEY,
  tenant_id       BIGINT NOT NULL,
  meeting_id      BIGINT NOT NULL,
  content         TEXT,                        -- 会议记录（富文本）
  venue_photos    VARCHAR(2000),               -- 会场照片（JSON）
  ppt_files       VARCHAR(2000),               -- 会议PPT（JSON，对应归档"会议PPT"）
  created_at      DATETIME DEFAULT NOW(),
  updated_at      DATETIME
);
```

### 4.4 归档映射（M7）

> 档案盒「盒三·安全生产会议」两条归档项：
> 1. **安全生产领导小组会议**（会议记录、会议PPT、签到、照片）
> 2. **安全生产月度会议**（会议记录、会议PPT、签到、照片）

这两条由 `meeting` + `meeting_attendee` + `meeting_record` 汇总生成，归档时按 `meeting_type` 自动归入对应子项，登记到 08 归档引擎（模板 `TPL_MEETING`）。

### 4.5 会议归档四段式（线下台账比对确认）

> 线下成品单个会议文件按固定顺序含 **4 段**，系统生成会议 PDF 时对齐此版式：

| 段 | 内容 | 数据来源 | 线下要素 |
|---|------|---------|---------|
| ① 会议通知 | 会议名称 + 时间 + 地点 + 会议内容（议题清单）+ 参会人员 + 落款 | `meeting`（M6） | 会议时间/地点/内容/参会人员/公司落款 |
| ② 签到表 | 会议时间 + 参会人数 + 主持人 + 序号/姓名/岗位/签名 | `meeting_attendee` | 时间/人数/主持人/出席人员表 |
| ③ 会议记录 | 会议名称 + 地点 + 时间 + 主持人 + 记录人 + 会议议题 + 会议记录正文 | `meeting_record` | 名称/地点/时间/主持/记录/议题/正文 |
| ④ 会场照片 | 附于表后 | `meeting_record.venue_photos` | 会议照片附于表后 |

> **签到表岗位列顺序（线下固定口径）**：`安全管理员 → 监控员 → 总经理 → 车队长 → 驾驶员`（其余岗位按组织架构追加）。系统生成签到表时按此顺序排岗位列，保证与政府抽查线下版式一致。

> **会议记录含"议题"字段**：线下会议记录区分"会议议题（强调的问题/做出的决定/部署的工作）"与"会议记录正文"两栏，系统 `meeting_record` 在富文本之外应保留结构化 `topic`（议题）字段（`meeting.topic` 已有，归档时一并输出）。

## 五、核心流程

### 5.1 会议全流程（M2/M6）

```
① 创建会议（PC，安全员）
   选类型(领导小组/月度) → 填名称/议题/方式/时间/主持人/记录人/参会人(多选·全选)
   → 方式=线上时填「腾讯会议号/链接」
   → 保存为草稿

② 发布通知（M6）
   自动生成通知（模板占位"关于召开 X 月安全生产工作会议的通知"）
   → 发布给参会人（小程序通知/首页今日三步出现"会议签到"）

③ 现场签到（小程序，司机 30 秒）
   会议开始后 → 司机点"签到" → 手写签名 → 提交
   → sign_image + sign_time 自动留痕

④ 录纪要（PC，记录人）
   会议结束 → 录入富文本会议记录 → 上传会场照片 + 会议PPT + 附件

⑤ 归档（PC，一键）
   纪要齐备 → 一键归档到「盒三·安全生产会议」对应子项
   → 生成会议记录 PDF（记录+签到表+照片+PPT页）
```

### 5.2 签到流程（M3/M11，30 秒极简）

```
司机小程序首页 → "今日三步"第 2 步「安全会议」→ 点"签到"
  → 手写签名板（大字号 + 大字按钮）
  → 自动带出姓名/岗位 + 自动时间戳
  → 提交（≤ 30 秒）
  → sign_image + sign_time 留痕
  → 若为线上会议：签到成功页提示跳转腾讯会议
     - 提示语："请在腾讯会议里把昵称改成本人姓名并上传头像，便于核对"
     - 按钮「进入线上会议」→ 跳转腾讯会议链接
```

> **适老化设计（沿用 11 三检的五条铁律）**：签名板大字、按钮热区 ≥48px、短路径 ≤3 步、自动带出少打字。司机只做一件事——**签个名**，其余全部系统自动。

> **线上会议跳转（M11）**：签到与进会**解耦**——签到是留痕动作（系统认签名时间戳），进会是可选下一步（跳转腾讯会议）。系统**不追踪入会状态、不采集会议内行为**，只通过"提示司机改用本人姓名+头像"实现腾讯会议内参会人身份与系统人员对齐，便于事后核对。跳转链接/会议号是通用字段，不硬绑定腾讯会议，企业用企微/钉钉链接同样可跳。

### 5.3 补签流程（M9）

```
会议结束 → 安全员查看签到表 → 发现未签人员
  → 核实到场 → 补签（标记 sign_source=replenish + replenished_by）
  → 或标记 leave 请假（填缺席原因）
  → 补签记录留痕可追溯
```

### 5.4 归档流程（M7，对接 08）

```
会议状态 → archived 条件：纪要 content 非空 + 签到表非空
  → 一键归档
  → 08 归档引擎生成：
     会议记录 PDF = 会议记录(富文本) + 签到表(签名+时间+状态) + 会场照片 + PPT
  → 按 meeting_type 归入「盒三」对应子项
  → 归档完整度 = 记录/签到/照片/PPT 四要素齐全度
```

## 六、业务规则

1. **两类会议（M1）**：会议类型收敛为"安全生产领导小组会议 / 安全生产月度会议"，对齐档案盒两个子项。
2. **签到留痕（M3）**：签名图片 + 自动时间戳 + 状态，一旦生成不可随意修改；补签标记来源可追溯。
3. **会议记录（M4）**：富文本记录 + 议题 + 会场照片 + PPT + 附件，会后由记录人录入。
4. **会议方式（M5）**：线上（腾讯会议号/链接）/ 线下（地点），线上时必填会议号或链接。
5. **通知生成（M6）**：会议创建即生成通知，模板占位"关于召开 X 月安全生产工作会议的通知"，可发布。
6. **线上会议跳转（M11）**：线上会议不内建会议室，签到成功后提示跳转腾讯会议（会议号/链接），并提示司机改本人姓名+录头像；签到与进会解耦，系统不追踪入会状态。
7. **补签（M9）**：会后安全员/超管可补签或标请假，补签必留 `sign_source` + `replenished_by`。
8. **归档（M7）**：按次归档，归档内容 = 会议记录 + PPT + 签到 + 照片；按类型归入盒三对应子项。
9. **完成率（M10）**：会议完成率 = 已归档会议数 / 应开会议数，计入企业安全分（权重可配置）。
10. **数据可改、日志不改**：超管可纠错会议数据，操作日志全量留存（沿用全局原则）。
11. **归档降级**：有记录/签到/照片/PPT 就生成对应部分，缺的部分打印占位提示（沿用 08"产出方式三原则"）。

## 七、页面交互设计

### 7.1 PC 端（管理端，核心）

- **列表页**（对齐原型 `pc/meeting.html`）：会议名称、会议类型（领导小组/月度）、召开时间、主持人、参会人数、状态、操作（详情/纪要/归档）
- **新增会议**：类型 → 名称/议题/方式（线上=填腾讯会议号+链接 或 线下=填地点）/时间/主持人/记录人/参会人（多选·全选）
- **会议详情**：基本信息 + 参会人员签到表（序号/姓名/签名/时间/状态/缺席原因，对齐逆向报告）+ 操作时间线
- **会议纪要**：富文本记录编辑 + 会场照片上传 + PPT 上传 + 附件
- **签到管理**：实时签到看板（谁签了/谁没签）+ 补签/标请假
- **一键归档**：归档到盒三，预览生成的会议记录 PDF

### 7.2 小程序（司机端）

- **会议签到**（今日三步第 2 步）：手写签名板 + 自动带出姓名/岗位 + 自动时间戳 + 大字反馈
- **线上会议跳转**（签到成功后）：提示"请在腾讯会议里把昵称改成本人姓名并上传头像"，按钮「进入线上会议」跳转腾讯会议
- **会议通知**：查看会议通知（标题/内容/时间/方式/会议号）
- 适老化：大字号、大按钮、短路径、少打字（沿用五条铁律）

## 十、开发任务拆解

1. 建表（meeting / meeting_attendee / meeting_record）
2. 会议类型字典初始化（领导小组会议 / 月度会议）

6. 线上会议跳转（签到成功后提示跳转腾讯会议 + 改姓名/录头像提示）
7. 签到表（序号/姓名/签名/时间/状态/缺席原因）

## 十一、验收标准

1. 支持两类会议创建：安全生产领导小组会议、安全生产月度会议，对齐档案盒两个子项。
2. 司机能 30 秒内完成签到：手写签名 + 自动带出姓名/岗位 + 自动时间戳，全程留痕不可改。
3. 签到表完整呈现：序号、姓名、签名、时间、状态、缺席原因，与逆向报告一致。
4. 会后能录入富文本会议纪要，上传会场照片、会议 PPT、附件。
5. 支持补签和标请假，补签必留来源标记可追溯。
6. 会议创建即生成通知（模板占位"关于召开 X 月安全生产工作会议的通知"），可发布给参会人。
7. 线上会议支持填写腾讯会议号/链接，签到成功后提示跳转腾讯会议，并提示司机改本人姓名+录头像（签到与进会解耦，不追踪入会）。
8. 一键归档到「盒三·安全生产会议」，归档内容 = 会议记录 + PPT + 签到 + 照片，按类型归入对应子项。
9. 会议完成率实时统计，计入企业安全分。
10. 超管可纠错会议数据，操作日志不可改。

# 详细设计 06 —— 组织架构（岗位层级 / 系统职能 / 人员分配 / 领导机构 + 合规校验）

> 版本：v1.4
> 日期：2026-11-04
> 状态：可进入开发
> 说明：安全管理组织架构，是「人员档案」的前置——人员必须挂在岗位上。**v1.3 变更（需求对齐）**：① **去掉「部门」层**——架构=公司→总经理→各岗位（按上级岗位 `parent_id` 组织层级）；② **12 个系统职能**，职能名称与默认目标/职责/考核标准**企业侧不可更改**，**岗位名称企业可自定义**；③ **强制岗位仅 3 个**：总经理、安全员、监控员；④ **服务商侧可配置架构模板**（普货：1,2,4,10；危货：1,2,3,4,8,9,10,11,12），企业按模板初始化；⑤ 岗位编辑可**调整上级关系**改变层级、可**兼并其他岗位职能**（总经理、安全员除外）；⑥ **人员一律从系统已录入人员选取**（不手动输入姓名电话）；⑦ **制度与架构双向动态更新**——被禁用/被兼并的岗位自动从「安全生产责任制」等制度内容中剔除。**v1.4 变更（架构图归档化）**：⑧ 架构图**只渲染启用岗位**，禁用岗位不再灰色占位（避免整图变形）；⑨ 启用下级沿 `parentId` **自动上提到最近的启用祖先**，防环 + 按 `FUNCS.no` 稳定排序；⑩ 抽出共享生成器 `OrgChart`，「安全管理架构」页与电子档案柜「安全管理组织架构」归档件同源，支持 **A4 横向打印 / 另存为 PDF**；⑪ **架构图取消「强制」角标**，强制岗位改在「岗位信息管理」页以岗位名称后的 `*` 标注（图面与打印件均不显示）。详见 5.1.2。

## 一、模块定位

安全生产的组织架构回答三个问题：

1. **有哪些岗位**（12 个系统职能 + 企业自定义）
2. **层级关系如何**（岗位间上级关系，不依赖部门）
3. **谁在什么位置**（人员分配 + 领导机构）

> 这是"责任落到人"的基础——事故追责、任务下发、权限分配都依赖"谁在什么岗位"。

**合规校验**：强制岗位（总经理、安全员、监控员）缺失持续标红提醒。

## 二、产品决策记录（已确认）

| 决策项 | 结论 |
|--------|------|
| 部门层 | **去除**（v1.3）：架构层级由岗位间「上级岗位」关系表达，不再维护部门 |
| 系统职能 | **12 个固定职能**，职能名称/默认目标/职责/考核标准**企业侧不可更改**；岗位名称可自定义 |
| 强制岗位 | **仅总经理、安全员、监控员** 3 个（法规最低要求，不可禁用）；其余岗位企业可禁用/恢复 |
| 架构模板 | **服务商侧配置**：普货模板默认启用 1,2,4,10；危货模板默认启用 1,2,3,4,8,9,10,11,12；强制岗位模板中不可取消 |
| 兼并职能 | 岗位可兼并其他岗位职能（被兼并岗位停用）；**总经理、安全员不可参与兼并**（既不可兼并他人，也不可被兼并） |
| 人员来源 | **仅从系统已录入人员（人员基础信息）选取**，不手动输入姓名/电话；多人班组岗位（驾驶员/押运员/装卸管理员）以所选人员为班组负责人 |
| 制度联动 | **双向动态**：岗位调整（名称/层级/兼并/禁用）实时反映到「安全生产责任制」等制度正文；禁用岗位自动从制度内容剔除 |
| 限制强度 | 接入时软提醒（可保存草稿），日常使用硬提示（持续标红提醒强制岗位缺失） |

### 2.2 架构模板（服务商侧配置）

| 模板 | 默认启用岗位 | 说明 |
|------|-------------|------|
| 普货模板 | 1 总经理、2 安全员、4 监控员、10 驾驶员 | 新接入普货企业按此初始化 |
| 危货模板 | 1 总经理、2 安全员、3 运营调度员、4 监控员、8 车辆技术管理员、9 停车场管理员、10 驾驶员、11 押运员、12 装卸管理员 | 新接入危货企业按此初始化 |

- 服务商在「服务商运营 → 架构模板配置」勾选各模板包含的职能；**强制岗位（1/2/4）不可取消**。
- 企业侧不能修改模板，只能在模板基础上**禁用不需要的岗位 / 新增岗位 / 自定义岗位名称**。
- 应用模板仅重置岗位启用状态，保留已配置的名称、人员等信息。

### 2.3 合规校验规则

| 规则 | 说明 |
|------|------|
| 强制岗位必须配人 | 总经理、安全员、监控员必须至少分配 1 人 |
| 监控员始终需配人 | 未委托第三方：专职；委托第三方：仍需 1 名兼职对接 |
| 非强制岗位可选 | 其余岗位企业按实际禁用/恢复，不校验 |

## 三、字段设计

### 3.1 岗位信息管理（列表）

**列表列**：岗位名称（含 `*` 强制 / 已禁用 / 职能并入标识）、岗位职能（不可改）、上级岗位、兼并职能、人员、操作

**编辑表单**：

| 字段 | 必填 | 说明 |
|------|------|------|
| 岗位名称 | ✅ | **企业可自定义** |
| 岗位职能 | — | 系统设定，**企业侧不可更改**（只读展示） |
| 上级岗位 | | 调整后即调整岗位层级关系（排除自身与下级防环） |
| 兼并其他岗位职能 | | 勾选后被兼并岗位停用、其职能/制度内容并入本岗位；**总经理、安全员除外** |
| 岗位权限 / 安全目标 / 岗位职责 / 考核标准 | | 职能关联的默认值可调；保存后联动责任制/责任书/考核奖惩 |
| 关联制度与责任书 | | 勾选该岗位需签署/遵循的制度与责任书 |

### 3.2 人员分配

**字段**：从系统已录入人员**下拉选取**（自动带出姓名/手机号/小程序账号），分配到岗位；多人班组岗位显示「×× 等 N 人」。

### 3.3 领导机构管理

**表单字段**：领导机构名称（组长/副组长/组员/职责）——保留原设计。

## 四、数据模型

```sql
-- 系统职能字典（平台12职能，企业不可改）
CREATE TABLE org_dict (
  id           BIGINT PRIMARY KEY,
  dict_type    VARCHAR(20) NOT NULL,        -- post=岗位
  dict_code    VARCHAR(50) NOT NULL,        -- gm/safe/disp/mon/clerk/finance/captain/vehtech/parklot/driver/escort/loader
  dict_name    VARCHAR(50) NOT NULL,        -- 总经理/安全员/...
  sort         INT DEFAULT 0
);

-- 岗位（无部门层，parent_id 组织层级）
CREATE TABLE org_post (
  id             BIGINT PRIMARY KEY,
  tenant_id      BIGINT NOT NULL,
  parent_id      BIGINT DEFAULT 0,          -- 上级岗位ID（0=直属公司顶层）
  dict_id        BIGINT,                    -- 关联系统职能
  func_key       VARCHAR(30),               -- 系统职能编码（企业侧不可更改）
  merged_func_ids VARCHAR(200),             -- 兼并的其他岗位职能编码（逗号分隔）
  post_name      VARCHAR(50) NOT NULL,      -- 显示名（企业可自定义）
  is_leader      TINYINT DEFAULT 0,
  required       TINYINT DEFAULT 0,         -- 仅总经理/安全员/监控员=1
  enabled        TINYINT DEFAULT 1,         -- 0禁用：架构图置灰+制度内容剔除
  permissions    VARCHAR(500),              -- 岗位权限（职能关联）
  function       VARCHAR(500),
  other_func     VARCHAR(500),
  goals          VARCHAR(500),              -- 岗位目标（联动安全生产责任制）
  duties         VARCHAR(1000),             -- 岗位职责（联动责任制/责任书）
  assess_std     VARCHAR(500),              -- 考核标准（联动考核奖惩/诚信考核）
  created_at     DATETIME DEFAULT NOW()
);

-- 人员-岗位分配（人员仅从系统已录入人员选取）
CREATE TABLE org_member (
  id           BIGINT PRIMARY KEY,
  tenant_id    BIGINT NOT NULL,
  user_id      BIGINT NOT NULL,             -- 关联 person / sys_user
  post_id      BIGINT NOT NULL,
  biz_field    VARCHAR(50),
  gender       VARCHAR(10),
  photo        VARCHAR(200),
  created_at   DATETIME DEFAULT NOW()
);

-- 架构模板（服务商侧配置，按运输类型）
CREATE TABLE org_tpl (
  id           BIGINT PRIMARY KEY,
  provider_id  BIGINT NOT NULL,             -- 服务商
  tpl_type     VARCHAR(20) NOT NULL,        -- putong=普货 / weihuo=危货
  func_keys    VARCHAR(500) NOT NULL,       -- 启用职能编码（逗号分隔，强制岗位必含）
  updated_at   DATETIME DEFAULT NOW()
);
```

> `org_dept`（部门）表已随 v1.3 移除；`person.dept_id` 保留为文本化统计字段，架构层级不再依赖部门。

## 五、页面交互设计（PC 端）

### 5.1 安全管理架构（图示化总览）

树形图示（不使用表格列表），**只渲染启用岗位**。以普货默认模板（1 总经理 / 2 安全员 / 4 监控员 / 10 驾驶员）为例：

```
公司（根节点）
└─ 总经理 / 主要负责人（人名）
   ├─ 安全员（人名）
   │   └─ 监控员（人名）
   └─ 驾驶员（×× 等 N 人）   ← 原上级「运营调度员 → 车队长」均已禁用，自动上提
```

> 若把安全员禁用，监控员会自动上提挂到总经理下；层级不会因中间层缺失而断链。

- 节点样式：岗位名（标题条）+ 职能副标题 + 人员；公司节点紫色；兼并职能在节点下方提示。**架构图不体现「强制」标识**——强制岗位只在「岗位信息管理」页以岗位名称后的 `*` 标注，图面与归档打印件保持干净。
- **禁用岗位不再出现在架构图中，也不以灰色占位**（避免节点占位导致整图变形）。图中只保留启用岗位；顶部统计条显示「启用 N 个 / 已禁用 N 个不显示 / N 个岗位已上提」，恢复禁用岗位统一走「岗位信息管理」页。
- 禁用岗位不参与三检/隐患/审批派发，且**不出现在制度正文**；右键交互只对渲染出来的启用岗位生效。
- 顶部入口：岗位信息管理、**责任制联动预览**（由启用岗位动态生成全员安全生产责任制正文，含剔除岗位清单）、**下载 / 打印架构图**、重置演示数据。

#### 5.1.1 节点右键菜单（核心交互）

| 菜单项 | 说明 | 联动 |
|--------|------|------|
| 更换岗位人员 | **从系统已录入人员下拉选取**（自动带出手机号），不手动输入 | 同步一人一档归属、责任书待签任务重开 |
| 编辑岗位 | 岗位名称（可自定义）/ 上级岗位（调整层级）/ 兼并其他岗位职能（总经理、安全员除外）/ 权限·目标·职责·考核标准 | 制度双向联动：责任制条目、责任书待签、考核奖惩/诚信考核岗位考核项实时更新 |
| 关联制度与责任书 | 勾选该岗位需签署/遵循的制度与责任书 | 未签的自动生成待签任务 |
| 禁用 / 恢复该岗位 | 仅**非强制**岗位显示；禁用后节点立即从架构图消失、从制度内容剔除 | 与岗位信息管理页同步 |

#### 5.1.2 架构图共享生成器与归档打印（v1.4 新增）

「安全管理架构」页与电子档案柜「安全管理组织架构」归档件**必须是同一张图**，禁止两处各自维护一套静态图。原型实现为 `assets/org_chart.js`（`window.OrgChart`），两页共用：

| 能力 | 规则 |
|------|------|
| `data()` | 读取 `OrgData.posts()`，只保留 `enabled=true` 的岗位 |
| 上提 | 沿 `parentId` 链向上跳过所有禁用节点，挂到**最近的启用祖先**；链断裂则挂到公司根节点 |
| 根节点 | `gm`（总经理/主要负责人）恒为岗位树根，不受其 `parentId` 误配影响 |
| 防环 | 上级链遇到重复节点即断开；组树时再做一次访问标记兜底，环内节点降级为根，绝不丢岗位 |
| 排序 | 按系统职能序号 `FUNCS.no` 升序，保证多岗位时排布稳定 |
| `html()` | 输出同一套 CSS 连线树；`interactive=true` 供配置页挂右键，`compact=true` 供 PDF 预览 / 打印 |
| `css()` / `inject()` | 屏幕与打印同源样式，`@media print` 去掉阴影/交互、保留矢量连线 |
| `wrapDoc()` / `printChart()` | 生成自包含 **A4 横向** HTML 文档（含 `@page`、页眉页脚、图例说明），浏览器打印对话框选「另存为 PDF」即得归档 PDF |

**数据来源**：岗位名称、职能副标题、人员、班组人数、兼并职能全部来自组织架构主数据，岗位改名 / 换人 / 禁用 / 兼并后，配置页、电子版归档预览、打印件三处同步变化。原型通过 `storage` 事件（`rd_org_data_v2`）实现跨页实时刷新，已打开的 PDF 预览也会重绘。

**归档联动**：电子档案柜盒一「安全管理组织架构」的 PDF 正文改为调用 `OrgChart.html({compact:true})`，替换原先写死 `张伟 / 李强 / 王芳 / 陈刚` 的静态图；归档项沿用「有变动时更新」频率，点「重新生成」即按当前架构数据重绘。

### 5.2 岗位信息管理（独立页）

菜单：基础档案管理 → 岗位信息管理。

- 列表列：岗位名称、岗位职能（不可改）、上级岗位、兼并职能、人员、操作
- 操作：**编辑**（名称/上级/兼并/权限目标职责考核标准）、**人员管理**（系统已录入人员选取）、**禁用岗位**（非强制）/ **恢复岗位**
- 强制岗位（总经理、安全员、监控员）在**岗位名称后打 `*`**（红色必填星号，hover 提示「法规最低要求岗位，不可禁用」），不可禁用；操作列不再重复放「强制」标签，架构图与打印件均不显示该标识
- 被兼并岗位显示「职能并入『××』」标识（停用态）
- **新增岗位**：从未配置的系统职能中选择；职能不可自定义，名称可自定义
- 与「安全管理架构」共用同一份数据（原型 `assets/org_data.js` + localStorage + storage 事件跨页实时联动；生产落 `org_post`/`org_member`/`org_tpl` 表）

### 5.3 架构模板配置（服务商侧）

菜单：服务商运营 → 架构模板配置。

- 左右两卡：**普货模板 / 危货模板**，12 个职能勾选（强制岗位禁用取消）
- 保存模板：新接入企业按模板初始化
- 应用模板（演示）：按所选模板重置企业岗位启用状态，保留名称/人员配置

### 5.4 合规校验提示

组织架构页顶部显示合规状态：强制岗位（总经理/安全员/监控员）缺失时标红列出缺失项 + 补配入口；分阶段：接入软提醒、日常硬提示。

## 六、业务规则

| 规则 | 说明 |
|------|------|
| 岗位职能不可改 | 12 个系统职能由平台设定，企业只能自定义岗位名称 |
| 无部门层 | 架构层级由岗位 parent_id 表达；调整上级岗位即调整层级 |
| 上级不可成环 | 上级岗位选择排除自身与全部下级 |
| 兼并限制 | 总经理、安全员不可兼并他人职能，也不可被兼并；被兼并岗位停用并标记 mergedInto |
| 强制岗位 | 仅总经理、安全员、监控员；不可禁用、必须配人 |
| 禁用即剔除 | 禁用岗位：架构图置灰、不参与业务派发、**制度正文中剔除**；恢复后回到制度内容 |
| 人员选取 | 仅从系统已录入人员选取；多人班组岗位以所选人员为班组负责人 |
| 删除保护 | 已被人员引用的岗位不可删（只能禁用） |

## 七、接口定义

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/org/post/tree` | 获取岗位层级树（按 parent_id） |
| GET | `/api/org/post/page` | 分页查询岗位 |
| POST | `/api/org/post` | 新增岗位（选择系统职能） |
| PUT | `/api/org/post/{id}` | 编辑岗位（名称/上级/兼并/权限目标职责考核标准） |
| PUT | `/api/org/post/{id}/merge` | 兼并岗位职能 |
| PUT | `/api/org/post/{id}/toggle` | 禁用/恢复岗位（强制岗位拒绝） |
| POST | `/api/org/member/assign` | 人员分配（user_id 必须为系统已录入人员） |
| GET | `/api/org/dict` | 获取系统职能字典（12 职能） |
| GET | `/api/org/tpl` | 服务商获取架构模板（普货/危货） |
| PUT | `/api/org/tpl` | 服务商保存架构模板 |
| POST | `/api/org/tpl/apply` | 应用模板初始化企业岗位 |
| GET | `/api/org/compliance/check` | 执行合规校验，返回缺失强制岗位清单 |
| PUT | `/api/org/compliance/outsource` | 标记监控员委托第三方 |

## 八、与其他模块的关系

| 模块 | 关系 |
|------|------|
| 人员基础信息（07） | 岗位人员从系统已录入人员选取；一人一档按岗位挂接 |
| 组织权限（01） | 系统职能关联角色权限（岗位权限 = 职能默认权限 + 调整） |
| 制度档案（文档发布） | **双向联动**：架构调整实时反映到安全生产责任制等制度正文；禁用岗位从制度剔除 |
| 考核奖惩 / 诚信考核（19） | 岗位考核标准联动岗位考核项 |
| 责任书签署 | 岗位关联制度变化自动生成待签任务 |
| 服务商运营 | 架构模板配置（普货/危货）下发企业 |

## 九、开发任务拆解

1. 建表（org_dict / org_post / org_member / org_tpl / org_compliance_check；org_dept 移除）
2. 12 系统职能初始化（含默认权限/目标/职责/考核标准/关联制度）
3. 服务商架构模板配置（普货/危货）+ 应用初始化
4. 岗位 CRUD + 层级树（parent_id 防环校验）
5. 岗位兼并职能（总经理/安全员保护）
6. 人员分配（系统已录入人员选取）+ 班组人数
7. 制度联动引擎（责任制/责任书按启用岗位动态生成）
8. 合规校验引擎（强制岗位判断）+ 提示 UI

## 十、验收标准

1. 架构图为「公司→总经理→各岗位」层级，无部门层；调整上级岗位后层级图实时变化
2. 岗位名称可自定义修改；岗位职能展示为系统设定且不可编辑
3. 仅总经理、安全员、监控员为强制岗位，其余岗位可禁用/恢复
4. 禁用岗位后：架构图置灰、「责任制联动预览」正文不再出现该岗位；恢复后重新出现
5. 兼并职能：目标岗位吸收被兼并岗位职能，被兼并岗位停用；总经理、安全员不可参与
6. 人员管理仅能从系统已录入人员下拉选取，带出手机号与小程序账号
7. 服务商侧可配置普货/危货模板；企业按模板初始化（普货 1,2,4,10 / 危货 1,2,3,4,8,9,10,11,12）
8. 强制岗位缺失时合规校验标红提示

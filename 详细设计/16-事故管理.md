## 一、模块定位

事故管理是"**兜底处置**"环节——事故发生后的**登记与上报**。但事故处理是**高度专业化、强责任、低频**的工作，企业自己很难做对（尤其"四不放过"资料、事故快报、与交警/保险/主管部门的对接）。

**核心定位**：
- **系统内只做「事故登记」**——企业录入事故基本信息，系统自动生成**事故快报表**和**年度事故汇总统计表**，满足归档的最低要求。
- **事故处理走「人工增值服务」**——事故资料整理、四不放过资料、事故处理指导、对接协调等，**引导企业联系平台人工服务**，作为**增值服务收费**。

> 设计逻辑：**登记自己做（简单、高频刚需），处理交给人工（专业、低频、可收费）**。系统负责"把事故记下来、把快报/汇总生成出来"，把"事故到底怎么善后"这件又难又累又担责的事，变成平台的付费增值服务。

## 三、核心模型

### 3.1 事故管理"登记 + 增值服务"分层

```
┌─────────────────────────────────────────────────┐
│  系统内（企业自助，免费）                          │
│  ① 事故登记（基本信息 + 照片）                     │
│  ② 自动生成事故快报表                              │
│  ③ 自动生成年度事故汇总统计表                      │
└─────────────────────────────────────────────────┘
              ↓ 联系人工（增值服务，收费）
┌─────────────────────────────────────────────────┐
│  平台人工（专业服务，收费）                        │
│  ① 事故资料整理                                   │
│  ② 四不放过资料制作                               │
│  ③ 事故处理指导（对接交警/保险/主管部门）          │
│  ④ 事故责任分析 + 整改建议                         │
└─────────────────────────────────────────────────┘
```

> **边界清晰**：登记是刚需、简单、必须企业自己做（事故信息只有企业/司机最清楚）；处理是低频、专业、可收费（平台人工代劳）。两者通过"联系人工"入口衔接。

### 3.2 事故登记字段与快报映射

| 登记字段 | 快报体现 | 汇总统计 |
|---------|---------|---------|
| 事故时间 | 快报必填 | 按年/月分组 |
| 事故地点 | 快报必填 | — |
| 事故车辆（车牌/车型） | 快报必填 | 按车辆统计 |
| 事故人员（姓名/岗位/伤亡） | 快报必填 | 按伤亡统计 |
| 事故经过（简述） | 快报正文 | — |
| 损失情况（直接经济损失） | 快报必填 | 按损失统计 |
| 责任初判 | 快报（可选） | — |
| 现场照片 | 快报附件 | — |
| 处理状态 | — | 按状态统计 |

## 四、数据模型（DDL）

### 4.1 事故登记表 accident_record（A1/A2）

```sql
CREATE TABLE accident_record (
  id              BIGINT PRIMARY KEY,
  tenant_id       BIGINT NOT NULL,
  accident_no     VARCHAR(50),                  -- 事故编号（自动生成）
  accident_time   DATETIME NOT NULL,            -- 事故发生时间
  location        VARCHAR(200),                 -- 事故地点
  vehicle_id      BIGINT,                       -- 事故车辆（10 车辆档案）
  vehicle_plate   VARCHAR(20),                  -- 车牌号（冗余，快照）
  accident_type   VARCHAR(30),                  -- 事故类型：碰撞/追尾/刮擦/侧翻/起火/其他
  involve_person  TEXT,                         -- 涉及人员（JSON：姓名/岗位/伤亡情况）
  description     TEXT,                         -- 事故经过（简述）
  loss_amount     DECIMAL(12,2),                -- 直接经济损失（元）
  responsibility  VARCHAR(200),                 -- 责任初判
  severity        VARCHAR(20),                  -- 事故等级：轻微/一般/较大/重大/特别重大
  status          VARCHAR(20) DEFAULT 'reported', -- reported已登记/processing处理中/closed已结案
  photos          VARCHAR(2000),                -- 现场照片（逗号分隔）
  reported_by     BIGINT,                       -- 上报人
  reported_at     DATETIME DEFAULT NOW(),       -- 上报时间
  created_at      DATETIME DEFAULT NOW(),
  updated_at      DATETIME,
  deleted         TINYINT DEFAULT 0
);
```

> 事故登记是**极简表单**，司机现场用小程序一分钟报完，PC 端可补充完善。

### 4.2 事故快报表 accident_quick_report（A3）

```sql
CREATE TABLE accident_quick_report (
  id              BIGINT PRIMARY KEY,
  tenant_id       BIGINT NOT NULL,
  accident_id     BIGINT NOT NULL,              -- 关联事故记录
  report_content  LONGTEXT,                     -- 快报正文（自动生成）
  report_no       VARCHAR(50),                  -- 快报编号
  report_time     DATETIME,                     -- 快报时间
  pdf_id          BIGINT,                       -- 生成的 PDF（08 引擎）
  created_at      DATETIME DEFAULT NOW()
);
```

> 事故登记后**自动生成标准格式快报**，满足归档"事故快报表"子项，自动盖章。

### 4.3 年度事故汇总统计表 accident_year_summary（A4）

```sql
CREATE TABLE accident_year_summary (
  id              BIGINT PRIMARY KEY,
  tenant_id       BIGINT NOT NULL,
  year            INT NOT NULL,                 -- 年度
  total_count     INT DEFAULT 0,                -- 事故总数
  total_loss      DECIMAL(14,2) DEFAULT 0,      -- 总损失
  minor_count     INT DEFAULT 0,                -- 轻微事故数
  general_count   INT DEFAULT 0,                -- 一般事故数
  major_count     INT DEFAULT 0,                -- 较大事故数
  pdf_id          BIGINT,                       -- 生成的 PDF
  created_at      DATETIME DEFAULT NOW()
);
```

> 汇总统计表由 `accident_record` **按年自动聚合**生成，支持随时重算刷新。

### 4.4 增值服务申请表 accident_service（A5/A8）

```sql
CREATE TABLE accident_service (
  id              BIGINT PRIMARY KEY,
  tenant_id       BIGINT NOT NULL,
  accident_id     BIGINT,                       -- 关联事故（可空，通用咨询）
  service_type    VARCHAR(50),                  -- 服务项目：资料整理/四不放过/处理指导/责任分析/其他
  service_desc    VARCHAR(1000),                -- 需求描述
  contact_name    VARCHAR(50),                  -- 联系人
  contact_phone   VARCHAR(20),                  -- 联系电话
  status          VARCHAR(20) DEFAULT 'pending', -- pending待受理/processing服务中/completed已完成
  fee             DECIMAL(12,2),                -- 服务费用
  created_at      DATETIME DEFAULT NOW(),
  updated_at      DATETIME
);
```

> 增值服务申请是"联系人工"的线上化：企业提交服务申请，平台人工受理，按次收费。

## 五、核心流程

### 5.1 事故登记流程（A1/A2/A3）

```
① 司机现场（小程序）一键上报：时间/地点/车辆/经过/照片（适老化大字、少打字）
② PC 端补充完善：人员/损失/责任初判/事故等级
③ 系统自动生成「事故快报表」（标准格式 + 盖章）
④ 归档到盒十/盒十一·事故档案（快报子项）
```

### 5.2 联系人工增值服务流程（A5/A7/A8）

```
① 事故登记页 / 快报表页突出「联系人工处理」入口
   （电话 + 在线客服 + 提交服务申请）
② 企业选择服务项目（资料整理/四不放过/处理指导…）并提交申请
③ 平台人工受理 → 线下/线上服务 → 按次收费
④ 服务成果（四不放过资料等）由人工回填，补齐归档
```

### 5.3 年度汇总流程（A4）

```
① 按年度聚合 accident_record → 生成年度事故汇总统计表
② 支持随时重算刷新
③ 归档到盒十/盒十一·事故档案（汇总统计表子项）
```

## 六、业务规则

1. **系统只做登记，不做处理**：事故处理流程、四不放过、调查分析一律不在系统内做，走人工增值服务（A1）。
2. **登记即生成快报**：事故登记后自动生成标准格式快报表（A3）。
3. **年度自动汇总**：汇总统计表按年自动聚合，随时可刷新（A4）。
4. **四不放过占位**：归档"事故四不放过资料"子项标注"联系人工服务"，由增值服务补齐（A6）。
5. **联系入口突出**：登记页 + 快报表页突出"联系人工处理"入口（A7）。
6. **增值服务收费**：按服务项目/次收费，登记页展示服务菜单（A8）。
7. **小程序一键上报**：司机现场快速上报，适老化（大字/少打字）（A9）。
8. **盖章**：快报表/汇总表自动盖公司章（A10）。
9. **数据可改日志不改**：超管可改事故数据，操作日志不可改（A11）。

## 七、页面交互设计

### 7.1 PC 端（管理端）

**事故登记页**：
- 事故列表（按时间/状态/等级筛选）
- 「新增事故」表单：基本信息 + 照片上传
- 事故详情：快报预览 + 「联系人工处理」入口（突出）

**年度汇总页**：
- 按年度查看事故汇总统计表 + 导出 PDF

**增值服务页**：
- 服务菜单（资料整理/四不放过/处理指导/责任分析）
- 服务申请提交 + 进度跟踪

### 7.2 小程序（司机端）

- **一键上报事故**：时间/地点/车辆/经过/照片，大字大按钮，少打字
- **联系人工**：一键拨打平台电话 / 在线客服

## 十一、验收标准

1. 事故登记极简，司机小程序一分钟内完成上报。
2. 登记后自动生成标准格式事故快报表（带盖章）。
3. 按年度自动生成事故汇总统计表。
4. 事故页突出"联系人工处理"入口（电话/客服/申请）。
5. 增值服务申请可提交、可跟踪、按次收费。
6. 四不放过资料归档项标注"联系人工服务"占位。
7. 归档可生成盒十/盒十一事故档案 PDF（快报 + 汇总统计表）。

## 一、模块定位

应急管理是"**能力建设**"环节的兜底模块——**平时建预案、排演练，事发时有章可循、有物可调**。它是企业年度性、周期性的合规动作，对应需求文档因果链的"应急处置能力"一环。

**核心目标**：应急管理**只管出带签名的台账**。系统内置多套应急预案范本，企业调用范本后自动生成**年度演练计划 + 演练方案 + 配套演练评估表**，企业演练后**补齐照片 + 签到表**即算完成，政府检查时一键出盒。

**关键定位**：
- **应急预案**：系统**内置多套场景范本**（道路交通事故、火灾、恶劣天气、货物散落、人员伤亡、综合预案等），企业按需**组合调用**，无需自己写预案。**仅普货系统生成；危货预案系统不生成（客户自备）**。
- **应急演练**：系统**自动生成年度演练计划 + 演练方案 + 演练评估表**，企业演练后只补**照片 + 签到表**即完成。
- **一键签名**：首次配置完成后，主要负责人 + 安全员**一键签名**（含应急预案、演练相关台账），见 09 文档 8.1。
- **应急培训**：**复用 14 培训教育**，标"应急培训"类型，不另起炉灶。

> 设计逻辑：应急管理 = **多套范本（预案）+ 自动生成（演练计划/方案/评估）+ 补齐留痕（照片/签到）+ 一键签名**。核心价值是"企业少动手、系统多代劳、台账带签名"。

## 三、核心模型

### 3.1 应急预案多套场景范本（E1/E2）

> 系统内置多套**场景预案范本**，企业按实际业务场景**组合调用**。

| 场景范本 | 编码 | 适用 | 说明 |
|---------|------|------|------|
| 道路交通事故专项 | road_accident | 普货 | 碰撞、追尾、刮擦处置 |
| 车辆火灾事故专项 | vehicle_fire | 普货 | 起火处置 |
| 恶劣天气专项 | bad_weather | 普货 | 台风/暴雨/大雾/结冰 |
| 货物散落、受损专项 | cargo_spill | 普货 | 货物散落/受损处置 |
| 人员伤亡专项 | casualty | 普货 | 人员伤亡现场处置 |
| 综合应急预案 | comprehensive | 普货 | 总纲（总则/组织/响应/保障） |

> **组合调用**：企业按实际承运场景勾选，系统把「综合预案 + 勾选的专项预案 + 现场处置方案」拼装成一套完整预案。**仅普货系统生成**；危货预案系统不生成（客户自备，见 09 文档 7.9.3）。原"危化品泄漏专项（hazmat_leak）"已随危货预案排除一并移除。

### 3.2 演练自动生成模型（E3/E4/E5/E6）

```
企业调用预案范本
   ↓ 系统自动生成
年度演练计划（覆盖全年，按场景排期）
   ↓ 每个演练项目自动生成
配套演练方案（目的/场景/步骤/职责）
   + 演练评估表模板（企业手填）
   ↓ 企业演练执行
补齐照片 + 签到表 + 手填评估表
   ↓
演练完成 → 归档
```

| 阶段 | 系统生成 | 企业补齐 |
|------|---------|---------|
| 演练前 | 年度计划 + 演练方案 + 评估表模板 | 无 |
| 演练后 | — | 照片 + 签到表 + 手填评估表 |
| 完成 | 一键签名 + 盖章 + 归档 | — |

> **关键**：系统把"写方案、写评估表"这类**文案工作全代劳**，企业只做"真演练 + 拍照 + 签到"这**三件必须线下做的实事**。

## 四、数据模型（DDL）

### 4.1 应急预案场景范本表 emergency_plan_tpl（E1）

```sql
CREATE TABLE emergency_plan_tpl (
  id              BIGINT PRIMARY KEY,
  tpl_code        VARCHAR(50) NOT NULL,        -- 场景编码 road_accident/vehicle_fire/...
  tpl_name        VARCHAR(100) NOT NULL,       -- 范本名称
  tpl_type        VARCHAR(20),                 -- comprehensive综合/special专项/site现场处置
  cargo_type      VARCHAR(10),                 -- general普货/danger危货/all通用
  content_html    LONGTEXT,                    -- 范本正文（含变量占位）
  variables       TEXT,                        -- 变量定义（JSON）
  is_default      TINYINT DEFAULT 0,           -- 是否默认勾选
  sort_order      INT,
  created_at      DATETIME DEFAULT NOW(),
  deleted         TINYINT DEFAULT 0
);
```

### 4.2 应急预案表 emergency_plan（E2）

```sql
CREATE TABLE emergency_plan (
  id              BIGINT PRIMARY KEY,
  tenant_id       BIGINT NOT NULL,
  cargo_type      VARCHAR(10) NOT NULL,        -- general普货/danger危货
  plan_name       VARCHAR(200) NOT NULL,       -- 预案名称
  version         VARCHAR(20) NOT NULL,        -- 版本号 V1/V2...
  scene_codes     VARCHAR(500),                -- 勾选的场景编码（逗号分隔，E1）
  content_html    LONGTEXT,                    -- 预案正文（组合渲染后）
  variables       TEXT,                        -- 变量值快照（JSON）
  status          VARCHAR(20) DEFAULT 'draft', -- draft/published/archived
  record_no       VARCHAR(100),                -- 备案回执编号（危货）
  record_file     VARCHAR(500),                -- 备案回执文件（危货，客户上传）
  effective_date  DATETIME,
  created_by      BIGINT,
  created_at      DATETIME DEFAULT NOW(),
  updated_at      DATETIME,
  deleted         TINYINT DEFAULT 0
);
```

> 预案 = 勾选场景 → 组合渲染成完整正文。危货备案回执由企业上传（客户自备）。

### 4.3 应急演练计划表 emergency_drill_plan（E3，系统自动生成）

```sql
CREATE TABLE emergency_drill_plan (
  id              BIGINT PRIMARY KEY,
  tenant_id       BIGINT NOT NULL,
  plan_name       VARCHAR(200) NOT NULL,       -- 如"2026年度应急演练计划"
  year            INT NOT NULL,
  cargo_type      VARCHAR(10),
  status          VARCHAR(20) DEFAULT 'draft', -- draft/published/finished
  created_by      BIGINT,                      -- 系统自动生成=0 或 超管
  created_at      DATETIME DEFAULT NOW(),
  deleted         TINYINT DEFAULT 0
);

CREATE TABLE emergency_drill_item (
  id              BIGINT PRIMARY KEY,
  tenant_id       BIGINT NOT NULL,
  plan_id         BIGINT NOT NULL,
  drill_name      VARCHAR(200) NOT NULL,       -- 演练项目名
  scene_code      VARCHAR(50),                 -- 对应场景范本（road_accident等）
  drill_type      VARCHAR(20),                 -- tabletop桌面/field实战/comprehensive综合
  plan_time       DATETIME,                    -- 计划时间
  scheme          TEXT,                        -- 演练方案（系统自动生成，E4）
  eval_template   TEXT,                        -- 演练评估表模板（系统自动生成，E5）
  responsible_id  BIGINT,
  created_at      DATETIME DEFAULT NOW()
);
```

> **自动生成规则（E3）**：系统按场景 + 频次（默认每季度 1 次，全年覆盖主要场景）自动生成年度计划，并为每个项目**自动生成演练方案 + 评估表模板**。

### 4.4 应急演练执行表 emergency_drill（E6/E12）

```sql
CREATE TABLE emergency_drill (
  id              BIGINT PRIMARY KEY,
  tenant_id       BIGINT NOT NULL,
  plan_item_id    BIGINT,                      -- 关联计划项（可空，独立演练）
  drill_name      VARCHAR(200) NOT NULL,
  drill_type      VARCHAR(20),
  drill_date      DATETIME,                    -- 实际演练时间
  eval_result     TEXT,                        -- 手填的演练评估表结果（E5）
  status          VARCHAR(20) DEFAULT 'draft', -- draft/executing/completed
  created_at      DATETIME DEFAULT NOW(),
  updated_at      DATETIME,
  deleted         TINYINT DEFAULT 0
);

CREATE TABLE emergency_drill_sign (
  id              BIGINT PRIMARY KEY,
  tenant_id       BIGINT NOT NULL,
  drill_id        BIGINT NOT NULL,
  user_id         BIGINT NOT NULL,
  user_type       VARCHAR(20),
  sign_time       DATETIME,
  sign_image      VARCHAR(500),
  created_at      DATETIME DEFAULT NOW()
);

CREATE TABLE emergency_drill_photo (
  id              BIGINT PRIMARY KEY,
  tenant_id       BIGINT NOT NULL,
  drill_id        BIGINT NOT NULL,
  photo_url       VARCHAR(500) NOT NULL,
  caption         VARCHAR(200),
  sort_order      INT,
  created_at      DATETIME DEFAULT NOW()
```

> **完成判定（E6）**：企业补齐**照片（≥1张）+ 签到表（≥1人）+ 手填评估表**后，`status=completed`。

## 五、核心流程

### 5.1 应急预案生成流程（E1/E2/E9）

```
① 企业勾选场景（仅普货；危货预案系统不生成，走占位说明页）
② 调用范本 → 填充企业信息变量 → 组合渲染完整预案正文
③ 一键签名（主要负责人 + 安全员，09 文档 8.1）
④ 盖公司章 → 发布（published）→ 归档
```

### 5.2 应急演练闭环流程（E3~E6）

```
① 系统自动生成年度演练计划（按场景排期）
② 每个项目自动生成演练方案 + 评估表模板
③ 企业演练执行：线下真演练
④ 企业补齐：照片 + 签到表 + 手填评估表
⑤ 三要素齐备 → completed → 一键签名 + 盖章 + 归档
```

## 六、业务规则

1. **预案多套范本按场景组合**：系统内置场景范本，企业勾选组合，不自己写（E1）。
2. **演练计划/方案/评估自动生成**：系统代劳文案，企业只做真演练 + 拍照 + 签到（E3/E4/E5）。
3. **演练完成三要素**：照片 + 签到表 + 手填评估表齐备才算完成（E6）。
4. **一键签名**：应急预案、演练台账等所有范本资料，主要负责人 + 安全员一键签名（E9，见 09 文档 8.1）。
5. **应急培训复用 14**：标"应急培训"类型，归档归集到应急培训子项（E8）。
6. **器材到期预警**：有效期临近/过期走预警引擎提醒（E7）。
7. **危货专属三件套**：备案回执（客户自备上传）、值班制度、值班表（E10）。
8. **盖章**：所有台账自动盖公司章（E13）。
9. **数据可改日志不改**：超管可改应急数据，操作日志不可改（E14）。

## 九、权限说明

| 角色 | 权限 |
|------|------|
| 超管 | 全部（含数据纠错） |
| 主要负责人 | 一键签名、预案发布、演练确认 |
| 安全管理员 | 调用范本生成预案、排演练、补照片/签到、维护队伍/器材 |
| 从业人员（司机） | 小程序演练签到 + 应急培训（复用14） |

---

## 十、开发任务拆解

1. 场景预案范本库（多套，按场景，E1）
2. 预案组合渲染（勾选场景 → 完整正文，E2）
3. 年度演练计划自动生成（按场景排期，E3）
4. 演练方案 + 评估表模板自动生成（E4/E5）
5. 演练执行（照片+签到+手填评估表，E6）
6. 一键签名对接 09（E9）
7. 应急队伍/器材登记（E7）
8. 应急培训复用 14（E8）
9. 危货专属（备案回执/值班制度/值班表，E10）
10. 归档对接 08（模板 `TPL_EMERGENCY`）

---

## 十一、验收标准

1. 系统内置多套场景预案范本，企业勾选后一键生成完整预案正文。
2. 系统自动生成年度演练计划 + 配套方案 + 评估表模板。
3. 企业演练后补齐照片 + 签到表 + 手填评估表即完成，无需写方案。
4. 应急预案、演练台账可一键签名（主要负责人 + 安全员）并自动盖章。
5. 应急培训复用 14，归档归集到应急培训子项。
6. 危货企业可上传备案回执、维护值班制度/值班表。
7. 归档可一键生成盒七/盒八全部应急资料 PDF（带签名 + 盖章）。

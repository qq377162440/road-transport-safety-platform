# 详细设计 05 —— 智能资料收集（大模型解析）

> 版本：v1.0
> 日期：2026-10-27
> 状态：可进入开发
> 说明：解决客户资料"杂乱无序"的问题。客户把 Excel / 图片 / PDF 直接丢进来，大模型解析拆分，生成系统所需的结构化数据，人工确认后入库。

---

## 一、模块定位（第一性原理）

客户（运输企业）手里的资料往往是**非结构化的**：

- 一张杂乱的 Excel 表（人员名单、车辆清单，列名不规范、合并单元格、多 Sheet）
- 一堆拍的照片（行驶证、驾驶证、身份证、营业执照）
- 一份 PDF（车辆台账、人员花名册扫描件）

传统方式要靠人工逐条录入，慢且易错。本模块用**大模型**把这些"脏数据"自动解析、拆分、对齐到系统字段，生成结构化数据，**人工确认后入库**。

> 核心价值：**把"人工录资料"变成"丢文件 + 大模型解析 + 点确认"**。

## 三、核心流程

```
上传文件（Excel/图片/PDF）
   → 大模型解析（识别内容 + 拆分 + 对齐字段）
   → 生成"待确认的结构化数据"（预览表格）
   → 人工核对、修正（可增删改）
   → 确认入库（写入 person / vehicle / tenant_info 等正式表）
```

### 3.1 关键设计：AI 解析 + 人工确认

**为什么必须人工确认**（而非全自动入库）：

1. 大模型可能识别错（车牌、身份证号、电话这类关键字段容错率低）
2. 客户原始数据本身可能有误（重复、缺失、格式乱）
3. 数据一旦入库会影响后续业务（三检、预警、台账），错误代价高

**确认界面**：
- 解析结果以表格预览展示，逐条可编辑、可删除、可补充
- 高亮"解析不确定"的字段（大模型置信度低的标黄，供人工重点核对）
- 确认无误后点「入库」

---

## 四、支持的解析场景

| 文件类型 | 解析目标 | 输出 |
|---------|---------|------|
| Excel（人员名单） | 姓名、手机号、岗位、性别、政治面貌、部门等 | 人员档案（person） |
| Excel（车辆清单） | 车牌号、营运类型、车辆类型、VIN、车牌颜色等 | 车辆档案（vehicle） |
| 图片（行驶证/驾驶证/身份证/营业执照） | OCR 识别证照信息 | 人员/车辆证照（person_cert / vehicle_cert / tenant_cert） |
| PDF（花名册/车辆台账扫描件） | 解析表格/文字 → 人员/车辆数据 | person / vehicle |

## 五、数据模型

```sql
-- 解析任务（一次上传 = 一个任务）
CREATE TABLE collect_task (
  id            BIGINT PRIMARY KEY,
  tenant_id     BIGINT NOT NULL,
  file_type     VARCHAR(10) NOT NULL,       -- excel/image/pdf
  target_type   VARCHAR(20) NOT NULL,       -- 解析目标：person/vehicle/cert
  file_url      VARCHAR(200),               -- 上传文件（对象存储URL）
  status        TINYINT DEFAULT 0,          -- 0上传待解析 1解析中 2待确认 3已入库 4解析失败
  created_by    BIGINT,
  created_at    DATETIME DEFAULT NOW()
);

-- 解析结果（大模型输出的结构化数据，待确认）
CREATE TABLE collect_result (
  id           BIGINT PRIMARY KEY,
  task_id      BIGINT NOT NULL,
  row_data     JSON,                        -- 解析出的一行数据（字段名对齐系统字段）
  confidence   DECIMAL(5,2),                -- 置信度（用于高亮提示人工核对）
  status       TINYINT DEFAULT 0,           -- 0待确认 1已入库 2已忽略 3已修改
  created_at   DATETIME DEFAULT NOW()
);
```

> 说明：解析结果存 `row_data JSON`，字段名对齐目标表的字段名，确认入库时把 JSON 映射到 person / vehicle 等正式表。

## 六、大模型调用接口（预留，不绑定具体厂商）

```
统一封装：LLMClient
  ├─ parseTable(file)      → 解析 Excel/PDF 表格 → 结构化行数据
  └─ parseImage(file)      → OCR + 识别证照 → 字段

配置项（开发时替换）：
  llm.provider = (通义千问 / 文心 / 豆包 / ...)
  llm.api_key  = xxx
  llm.model    = xxx
```

> 设计原则：**业务层只依赖 `LLMClient` 接口，不依赖具体厂商 SDK**。未来换厂商只需改配置和实现类，业务代码不动。

```

│                                      │
│ ┌───┬──────┬──────┬────┬─────────┐ │

│ ├───┼──────┼──────┼────┼─────────┤ │
```

```
                              │
```

## 九、接口定义

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/collect/upload` | 上传文件，创建解析任务 |
| POST | `/api/collect/{taskId}/parse` | 触发大模型解析 |
| GET | `/api/collect/{taskId}/result` | 获取解析结果（待确认列表） |
| PUT | `/api/collect/result/{id}` | 编辑某条解析结果 |
| POST | `/api/collect/{taskId}/import` | 确认入库 |
| GET | `/api/collect/tasks` | 解析任务列表 |

## 十一、开发任务拆解

1. 建表（collect_task / collect_result）
2. LLMClient 统一接口 + 配置化（预留多厂商）
3. Excel 解析（表格结构化）
4. 图片 OCR + 证照识别
5. PDF 解析
6. 解析结果预览 + 人工确认界面
7. 确认入库（映射到正式表）
8. 低置信度高亮 + 逐条编辑

---

## 十二、验收标准

1. 上传 Excel 人员名单，能正确解析出姓名/手机号/岗位等结构化数据
2. 上传行驶证/驾驶证图片，能 OCR 识别出关键字段
3. 解析结果能预览，低置信度字段高亮，可编辑/删除/补充
4. 确认后数据正确入库到 person / vehicle 表
5. 解析失败有明确提示，可重新上传
6. 大模型厂商可通过配置切换（不写死）

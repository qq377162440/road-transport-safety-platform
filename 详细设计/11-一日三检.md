> 所属域：check（一日三检）
> 优先级：**P0 保命功能**（法规强制 + "不出事" + "证明我管了"）

> 上游依赖：10 车辆基础信息与一车一档（人车绑定 `vehicle_driver` + 车型标签 `vehicle_class`）、09 范本引擎（检查表 7 大类）
> 下游被依赖：02 预警引擎（未检提醒）、08 台账归档（「盒·一日三检」，普货盒九 / 危货盒十）、13 隐患排查（异常→隐患流转）

## 一、模块定位

一日三检是平台**唯一由一线司机高频执行**的 P0 功能，也是"证明我管了"最直接的证据链。

**核心目标（来自需求文档验收金标准）**：
> 一个不会用电脑的中老年司机，能否 **30 秒内**独立完成一次三检？

设计铁律：**录入极简，绑定行为**。三检必须"点选即可、无需打字"，能自动带出的字段绝不手动填。

**边界**：本模块负责"三检任务的生成 → 司机小程序执行 → 异常上报 → PC 汇总归档"。检查过程中发现的异常，流转到 13 隐患排查治理（本模块只埋流转钩子）。

## 三、检查项模型（核心）

### 3.1 检查项 = 时段 × 车型标签 的矩阵

一日三检的检查项**不是写死的一套**，而是：

```
检查项清单 = 时段（出车/行车/收车）× 车型标签（vehicle_class）
```

- 同一时段，厢式车和罐车的检查项**不同**（罐车多"罐体/阀门/静电接地"等）
- 同一车型，出车前和收车后的检查项**不同**（出车前查"能否出车"，收车后查"停车状态"）

### 3.2 检查项字典 check_item_dict

```sql
CREATE TABLE check_item_dict (
  id              BIGINT PRIMARY KEY,
  item_code       VARCHAR(30) NOT NULL,        -- 检查项编码
  item_name       VARCHAR(100) NOT NULL,       -- 检查项名称（司机看，说人话）
  phase           VARCHAR(10) NOT NULL,        -- 时段：out出车前/mid行车中/in收车后
  vehicle_class   VARCHAR(50) NOT NULL,        -- 车型标签（普货7类/危货两层，见10模块3.7）
  biz_type        VARCHAR(20),                 -- 营运类型 freight/danger/passenger
  sort_no         INT DEFAULT 0,               -- 排序
  is_default      TINYINT DEFAULT 0,           -- 是否通用项（所有车型都查）
  created_at      DATETIME DEFAULT NOW()
);
```

**检查项拼装规则**：

1. `is_default=1` 的通用项 → 所有车型都加载
2. `vehicle_class` 匹配当前车辆标签的专项项 → 追加
3. 危货车在基础项上**追加**危货专项项（静电、警示标志、灭火器、防泄漏等）

### 3.3 检查项示例（测试阶段）

> **测试阶段只内置 4 个通用项**（用户确认）：轮胎、灯光、刹车、反光条。后续通过"自定义 + 上传模板"扩充到各车型专项项。

| 时段 | 测试阶段检查项（4 项通用） |
|------|--------------------------|
| 出车前 | 轮胎、灯光、刹车、反光条 |
| 行车中 | 轮胎、灯光、刹车、反光条 |
| 收车后 | 轮胎、灯光、刹车、反光条 |

### 3.4 检查清单自定义 + 模板上传

- **企业可自定义**：在 PC 端检查项字典中，按车型标签 + 时段增删检查项、调整排序。
- **支持上传模板**：企业可将已有的纸质检查表（Excel/Word）上传，系统解析成检查项字典（或人工对照录入）。
- **自定义优先级**：企业自定义项覆盖系统预置项；系统预置项仅作兜底默认值。

### 3.5 台账字段对齐（行车日志与政府检查台账样例逐字段对应）

> 「一日三检」归档到「盒九·一日三检」，台账为**企业车辆行车日志**，字段与线下台账样例逐字段对应：

| 台账字段 | 系统来源 | 说明 |
|---------|---------|------|
| 车牌号 | `check_task.vehicle_id` → 一车一档 | 台账表头 |
| 日期 | `check_task.start_date` | 台账表头 |
| 出车公里数 | `check_task.mileage_start`（出车里程表读数） | 台账"出车公里数" |
| 收车公里数 | `check_task.mileage_end`（收车里程表读数） | 台账"收车公里数" |
| 货物名称 / 货物数量 | 出车任务（运单） | 台账"货物名称/数量" |
| 始发地 / 中途停靠地 / 目的地 | 出车任务（运单） | 台账起止地 |
| 日检情况 | 三检结果汇总（正常/异常） | 台账"日检情况" |
| 出车检查 / 行车中检查 / 收车后检查明细 | `check_record`（三时段检查项 √/×） | 台账"一日三检记录表" |
| 驾驶员/押运员签字 | `check_record.sign_image` | 台账签字栏 |

> **字段下沉**：为对齐行车日志台账，`check_task` 增加 `mileage_start`/`mileage_end`/`cargo_name`/`cargo_qty`/`origin`/`stopover`/`destination` 字段（见 4.1），三检明细项与出车/行车/收车三时段检查项字典对应。

## 四、数据模型（DDL）

### 4.1 三检任务主表 check_task（一次出车周期一条）

```sql
CREATE TABLE check_task (
  id              BIGINT PRIMARY KEY,
  tenant_id       BIGINT NOT NULL,
  vehicle_id      BIGINT NOT NULL,             -- 关联 vehicle
  driver_id       BIGINT,                      -- 实际驾驶员（默认取静态绑定，可切换，见 5.1）
  escort_id       BIGINT,                      -- 押运员（危货）
  is_trailer      TINYINT DEFAULT 0,           -- 0车头 1挂车（车头挂分离）
  start_date      DATE,                        -- 出车日期（出车周期起点）
  end_date        DATE,                        -- 收车日期（跨日任务时 > start_date）
  status          VARCHAR(20) DEFAULT 'not_out', -- not_out未出车/doing出车中/done已完成
  remind_count    INT DEFAULT 0,               -- 提醒次数
  mileage         INT,                         -- 里程（本出车周期）
  mileage_start   INT,                         -- 出车公里数（行车日志）
  mileage_end     INT,                         -- 收车公里数（行车日志）
  cargo_name      VARCHAR(100),                -- 货物名称（行车日志）
  cargo_qty       VARCHAR(50),                 -- 货物数量（行车日志）
  origin          VARCHAR(200),                -- 始发地（行车日志）
  stopover        VARCHAR(200),                -- 中途停靠地（行车日志）
  destination     VARCHAR(200),                -- 目的地（行车日志）
  created_at      DATETIME DEFAULT NOW(),
  updated_at      DATETIME,
  UNIQUE KEY uk_task (tenant_id, vehicle_id, is_trailer, start_date)
);
```

> **关键重构（C10/C12）**：
> - `check_date` 改为 `start_date`（出车周期起点）+ `end_date`（收车日期），支持**跨日长途任务**——一次出车周期可横跨多天。
> - `status` 增加 `not_out`（未出车）状态：**不出车不生成三检任务**，或 PC 端标记"未出车"当日豁免。
> - 唯一约束改为 `(vehicle_id, is_trailer, start_date)`，同一辆车同一天只允许一个出车周期。
> - 跨日时，同一出车周期内**每天上下车各一次三检**（记录在 check_record 里带日期），不因跨自然日断任务。

### 4.2 三检记录子表 check_record（一次时段检查一条）

```sql
CREATE TABLE check_record (
  id              BIGINT PRIMARY KEY,
  tenant_id       BIGINT NOT NULL,
  task_id         BIGINT NOT NULL,             -- 关联 check_task（出车周期）
  phase           VARCHAR(10) NOT NULL,        -- out/mid/in
  check_day       DATE,                        -- 实际检查日（跨日任务中区分第几天）
  result          VARCHAR(10),                 -- pass合格/abnormal异常
  check_time      DATETIME,                    -- 检查完成时间（自动，超管可改）
  abnormal_note   VARCHAR(500),                -- 异常文字说明（语音转文字结果）
  abnormal_voice  VARCHAR(500),                -- 异常语音文件URL（语音+文字双保存）
  abnormal_photos VARCHAR(1000),               -- 异常照片（可多张，JSON）
  created_at      DATETIME DEFAULT NOW()
);
```

> **跨日关键字段**：`check_day` 区分一次出车周期内"第几天"的检查。跨日长途时，`check_task` 一条（一个出车周期），但 `check_record` 每天上下车各一条。

### 4.3 检查项明细 check_item_result（勾选结果，留痕）

```sql
CREATE TABLE check_item_result (
  id              BIGINT PRIMARY KEY,
  record_id       BIGINT NOT NULL,             -- 关联 check_record
  item_id         BIGINT NOT NULL,             -- 关联 check_item_dict
  checked         TINYINT DEFAULT 0,           -- 1已勾选（正常）
  abnormal        TINYINT DEFAULT 0,           -- 1异常
  created_at      DATETIME DEFAULT NOW()
);
```

### 4.4 提醒记录 check_remind

```sql
CREATE TABLE check_remind (
  id              BIGINT PRIMARY KEY,
  tenant_id       BIGINT NOT NULL,
  task_id         BIGINT NOT NULL,
  remind_date     DATETIME,                    -- 提醒日期时间
  remind_way      VARCHAR(20),                 -- 短信/小程序推送/电话
  remind_content  VARCHAR(500),                -- 提醒内容
  created_at      DATETIME DEFAULT NOW()
);
```

### 4.5 车头挂分离说明（C5，已确认）

> 牵引车 + 挂车分开检查：`check_task` 用 `is_trailer` 区分。一辆牵引车挂一辆挂车时，生成**两条任务**（车头一条 + 挂车一条），各自独立完成三检。该字段已并入 4.1，不再单独建表。

### 4.6 三检配置表 check_config（PC 端开关，C12/C15/C16）

```sql
CREATE TABLE check_config (
  id              BIGINT PRIMARY KEY,
  tenant_id       BIGINT NOT NULL,
  default_policy  VARCHAR(20) DEFAULT 'not_out', -- 默认策略：not_out默认未出车 / not_check默认未检查（C12）
  force_camera    TINYINT DEFAULT 0,           -- 强制实时摄像头：1开启（C15）
  allow_declare   TINYINT DEFAULT 0,           -- 允许司机声明未出车：1开启（C16）
  created_at      DATETIME DEFAULT NOW(),
  updated_at      DATETIME,
  UNIQUE KEY uk_config (tenant_id)
);
```

> 三个开关说明：
> - `default_policy`：企业级"默认未出车 / 默认未检查"策略（C12）
> - `force_camera`：开启后司机报修/异常拍照**必须调用实时摄像头**，禁用相册上传（防拿旧图充数）
> - `allow_declare`：开启后司机可在小程序**自行声明"今天没出车"**，声明后当日免做三检；关闭则只能 PC 端标记

## 五、核心流程

### 5.1 任务生成（绑定出车行为，而非自然日）

> **核心模型重构**：三检**绑定"出车行为"**，不是"每天每车自动生成"。一辆车**出车了才需要三检，没出车不用做**（C12）。

```
任务生成逻辑：
  1. 车辆出车（司机首次做"出车前"检查，或 PC 端标记"今日出车"）
     → 生成该车当日 check_task（status=doing）
  2. 车辆未出车
     → 不生成任务，或 PC 端标记"未出车"（当日豁免三检）
  3. 跨日长途（C10）
     → 一次出车周期内，每天上下车各需一次三检
     → 任务随出车周期持续，不因跨自然日而断
```

**出车状态（新增字段）**：

| 状态 | 含义 | 三检要求 |
|------|------|---------|
| `未出车` | 车辆当天没出车（默认或 PC 标记） | 不做三检，当日豁免 |
| `已出车` | 车辆当天出车了 | 需完成出车/行车/收车三检 |
| `出车中` | 跨日长途，任务进行中 | 每天上下车各一次三检 |

**PC 端默认标记（C12）**：

> 企业可配置"默认未出车 / 默认未检查"两种策略：
> - **默认未出车**：适合"大部分车不天天出车"的企业，出车了才标记做三检
> - **默认未检查**：适合"每天固定出车"的企业，默认生成任务，不出车再手动豁免

**司机声明未出车（C16，开关控制）**：

> 若 `allow_declare=1`，司机可在小程序点「今天没出车」声明当日未出车，声明后**当日免做三检**（记入 `check_task.status=not_out`）。声明留痕（谁、何时、哪辆车）。关闭时此入口隐藏，只能 PC 端标记。
>
> 防滥用：同一辆车当天声明后，若司机又做了三检，以实际三检为准（声明自动作废）。

**跨日任务处理（C10）**：

```
下午出车 → 完成"出车前"检查
  → 当天晚上到达或途中停车 → 完成"行车中/收车后"
  → 第二天早上继续出发 → 新的一天，再做一次"出车前"
  → 后天到达 → 完成"收车后"
```

> 关键：**跨日不中断任务**。一次长途出车周期（从"出车"到"收车"）可能横跨多天，每天上下车都各需一次三检。任务以"出车周期"为单位，而非"自然日"为单位。

**换头换挂场景（核心，用户确认）**：

> 人车每天固定是常态，但存在"换头换挂"（换牵引车头、换挂车、临时顶班）的情况，因此**不能死绑静态绑定**。

处理规则：
1. **默认预填**：任务生成时，`driver_id` 默认取 `vehicle_driver` 的当前活跃绑定驾驶员。
2. **检查前确认**：司机打开小程序做三检时，顶部提示"今天检查这辆车：粤E·12345（陈刚）？"，司机可一键「换辆车」切换当天实际驾驶车辆。
3. **切换不改静态绑定**：当天切换只改 `check_task.driver_id`（当日实际驾驶员），**不动** `vehicle_driver` 的长期绑定关系。
4. **无绑定则必选**：若该车无静态绑定驾驶员（`driver_id` 为空），司机首次检查时**必须选择**"我是谁 + 检查哪辆车"后才能开始。
5. **PC 端可补录/纠正**：安全员可在 PC 端修改某车当天实际驾驶员（超管亦可纠错）。
6. **车头挂模糊搜索（C13）**：司机选车头/挂车时，提供一个**模糊搜索框**——输入车牌号中的**任意一个数字或字母**，即弹出匹配的车辆列表供点选，无需手输完整车牌。例如输入"12"→ 弹出"粤E·12345 / 粤A·51236..."等所有含"12"的车牌。

### 5.2 司机执行（小程序，30 秒极简设计）

```
司机打开小程序 → 首页"今日三检"大卡片
  → 顶部提示"今天检查：粤E·12345"，可【换辆车】（模糊搜索框点选，应对换头换挂）
  → 若上一次三检未完成，提示"请先结束上一次检查"，不能开始新的（C11 串行）
  → 系统按当前时间自动预选时段（早上=出车前/中午=行车中/晚上=收车后）
  → 点【全部正常】大按钮 → 一个时段完成（绝大多数场景，1 步搞定）
  → 有异常才展开逐项勾选 + 报修
```

**30 秒极简设计（补强版，核心）**：

| # | 设计点 | 说明 |
|---|--------|------|
| 1 | **一键「全部正常」** | 默认所有检查项正常，司机点一个大按钮即完成整个时段，**无需逐项点**。逐项勾选只在"有异常"时才展开 —— 绑定行为：绝大多数车是正常的，异常是小概率 |
| 2 | **时段自动预选** | 按当前时间自动判断该做哪一时段，省掉"选时段"一步 |
| 3 | **拍照/语音仅异常时** | 正常提交零拍照零语音；只有点"报修"才触发拍照+语音，避免"为了录入而录入" |
| 4 | **语音记录异常（新增）** | 报修时支持**语音输入 → 自动转文字**，语音文件 + 文字**双保存**，司机连字都不用打 |
| 5 | **检查前确认车辆** | 检查前提示"今天检查这辆车？"，支持一键切换（应对换头换挂） |
| 6 | **大字反馈 + 语音播报** | 提交后大字显示"今天三检完成 ✓"，可语音播报（适老化，户外看不清也能听） |
| 7 | **离线可提交** | 户外/地下车库无信号时**离线暂存**，回网自动补传，不卡死司机 |

**白话文案（适老化铁律 4）**：
- 按钮叫「全部正常」而非"确认提交"
- 报修叫「车有毛病」而非"发起异常工单"
- 提示叫「今天三检还没做，抓紧咯」而非"存在未完成任务"

**异常报修流程（语音 + 拍照，零打字）**：
```
司机点【车有毛病】→ 长按说话（语音自动转文字）
  → 可选拍照（最多 3 张）
  → 点【提交报修】→ 语音文件 + 文字 + 照片 一起流转 13 隐患排查
```

### 5.3 PC 汇总 + 督办

```
PC 端一日三检页：
  - 列表：车牌号、驾驶员/押运员、状态、三时段结果、里程、操作
  - 筛选：日检日期、车牌号、人员、车头/挂分离
  - 按月视图切换
  - 未完成车辆 → 一键提醒（短信/推送）
  - 异常项 → 跳转 13 隐患排查处理
```

### 5.4 归档（08 联动）

- 每日/每月汇总三检记录 → 自动登记到 08 归档引擎「盒·一日三检」（普货盒九 / 危货盒十，业务绑 code 不绑盒号）
- 按 08 的产出方式三原则：三检记录属"系统生成"（有数据自动生成，无需手写）

## 六、业务规则

1. **任务唯一性**：一辆车同一 `start_date` 一条出车周期任务（`uk_task`），车头挂分离则各一条。
2. **出车状态（C12）**：车辆出车 → 生成任务（`status=doing`）；未出车 → 不生成或标记 `not_out`，当日豁免三检。PC 端可配置"默认未出车 / 默认未检查"。
3. **三检串行（C11）**：上一次三检未完成（`status=doing` 且当日三时段未集齐）时，**不能进行下一次**，提示"请先结束上一次检查提交"。
4. **跨日任务（C10）**：一次出车周期可横跨多天，每天上下车各一次三检；`check_record.check_day` 区分第几天，跨日不中断任务。
5. **异常流转**：任一时段 `result=abnormal`，自动生成 13 隐患排查单，语音+文字+照片 一并流转。
6. **提醒机制**：出车中未完成任务，按预警引擎策略（如当日 10:00/14:00/17:00）分级提醒，记录 `remind_count`。
7. **停运豁免**：`business_status='stop'` 车辆不生成任务。
8. **数据修改权（C8）**：检查时间、结果、人员等自动记录，但**超管永远有改任何数据的权限**，可人工纠错（如司机误操作导致记录错误）。当前阶段以服务客户为主，合规防篡改（监管端/过审）后续再议。
9. **车型驱动**：检查项按 `vehicle_class` 动态拼装，车型标签变化时次日任务自动用新清单。
10. **检查清单可配置**：检查项支持自定义 + 上传模板，企业配置覆盖系统预置。
11. **换头换挂（C9）**：`driver_id` 默认取静态绑定，检查前可切换当天实际驾驶员；切换只改 `check_task.driver_id`，不动 `vehicle_driver` 长期绑定。
12. **车头挂模糊搜索（C13）**：选车头/挂车用模糊搜索框，输入任意数字/字母即弹出匹配车牌点选。
13. **强制实时摄像头（C15）**：`force_camera=1` 时，报修/异常拍照只能调用摄像头实时拍，禁用相册上传（防旧图充数）。
14. **司机声明未出车（C16）**：`allow_declare=1` 时，司机可声明"今天没出车"免做三检；声明留痕，若当天又做了三检则声明自动作废。

### 6.1 报表产出定义（C14，收敛：对应档案盒目录）

> **关键收敛（用户确认）**：报表产出对应档案盒目录——档案盒「一日三检」这一盒，实际只需**月报汇总表**。监管要看具体某台车某一天，从系统里**现查现打**，不预先装盒。

| 报表 | 定位 | 是否装盒 | 说明 |
|------|------|---------|------|
| **月报汇总表** | 归档交付物 | ✅ 装盒 | 按车按月汇总三检完成情况（出车/未出车/完成/异常），对应档案盒「一日三检」 |
| 单车/单日明细 | 临时查询 | ❌ 不装盒 | 监管要查某车某天时，PC 端按车牌+日期筛选，**单独打印** |

> 因此导出能力收敛为：
> - **主出口**：`月报汇总表`（按车按月），这是装盒的唯一报表
> - **查询打印**：PC 列表页本身支持按车牌/日期筛选，筛选结果直接打印（不叫"导出报表"，叫"打印查询结果"）

**月报汇总表内容**（装盒版）：

| 列 | 说明 |
|----|------|
| 车牌号 | 车辆标识 |
| 本月出车天数 | 实际出车天数 |
| 三检完成情况 | 每天三时段完成/缺失标记 |
| 异常次数 | 本月报修/异常次数 |
| 未出车天数 | 声明未出车/标记未出车的天数 |

> 报表属 08 归档引擎"系统生成"产出方式（有数据自动生成，无数据可打印空白表手写）。

## 七、页面交互设计

### 7.1 小程序（司机端，P0 核心）

- 首页"今日三检"大卡片：显示当前绑定车辆 + 完成进度（如 2/3）
- **检查前确认车辆**：顶部提示"今天检查：粤E·12345"，可【换辆车】——车头/挂车用**模糊搜索框**，输入车牌任意数字/字母即弹出匹配项点选
- **三检串行提示**：上一次未完成时，提示"请先结束上一次检查"，不能开始新的
- **声明未出车（C16，开关控制）**：若企业开启，显示「今天没出车」按钮，点选声明后当日免做三检
- 时段**自动预选**（按当前时间）+ 一个【全部正常】大按钮
- 有异常才展开逐项勾选，异常走「车有毛病」报修（语音 + 拍照）
- **拍照方式（C15，开关控制）**：若企业开启"强制实时摄像头"，报修拍照只能调用摄像头实时拍，禁用相册上传
- 大字反馈 + 语音播报 + 离线可提交
- 30 秒完成（正常情况 1 步搞定），零打字

### 7.2 PC 端（管理端）

- 列表页（对齐原型 `pc/check.html`）：车牌号、驾驶员/押运员、状态、出车/行车/收车、里程、操作
- **出车标记**：PC 端可标记"未出车"（当日豁免三检），支持"默认未出车/默认未检查"策略配置
- **开关配置**：①强制实时摄像头 ②允许司机声明未出车（C15/C16）
- **报表产出**：月报汇总表（按车按月，装盒）；列表按车牌/日期筛选后直接打印（现查现打）
- 按月视图 + 车头挂分离筛选
- 提醒记录抽屉（提醒时间/方式/内容）
- 异常项高亮 + 跳转隐患处理（可查看语音/照片/文字）
- **检查项配置**：自定义 + 上传模板入口
- **数据纠错**：超管可编辑任何三检记录（改错改漏），可修改某车当天实际驾驶员

## 十一、验收标准

1. 中老年司机 **正常情况 1 步**（点「全部正常」）完成一次三检，异常情况 30 秒内完成，全程零打字。
2. 时段按当前时间自动预选，无需手动选时段。
3. 异常报修支持语音转文字，语音+文字双保存，可查看可追溯。
4. 检查项能按车型标签正确拼装，且支持企业自定义 + 上传模板。
5. 一次出车周期一条任务，牵引车+挂车分开检查。
6. 三时段集齐才判定完成，缺一段显示"进行中"。
7. 异常项一键流转隐患排查，语音+照片 一并带出。
8. 未检车辆能按策略提醒，并记录提醒次数。
9. 超管能人工纠错任何三检记录。
10. 离线可提交，回网自动补传。
11. 三检记录能自动归档到「盒·一日三检」（普货盒九 / 危货盒十），且按产出方式"系统生成"处理。
12. 司机检查前能看到当天绑定车辆，并能一键切换（换头换挂），切换后当天检查记到正确车辆名下，且不影响长期绑定关系。
13. **跨日任务**：下午出车后天才到的长途任务，每天上下车各一次三检，任务不因跨日中断。
14. **三检串行**：上次未完成时，不能开始下次，并提示"请先结束上一次检查"。
15. **出车标记**：PC 可标记"未出车"（当日豁免），支持"默认未出车/默认未检查"两种策略。
16. **模糊搜索**：选车头挂时输入任意数字/字母，即弹出匹配车牌点选。
17. **报表产出**：能导出月报汇总表（按车按月）装盒；列表支持按车牌/日期筛选并直接打印单车单日明细。
18. **强制实时摄像头**：开关开启后，司机报修拍照只能实时拍摄，无法从相册上传。
19. **司机声明未出车**：开关开启后，司机能声明"今天没出车"免做三检；声明留痕，做三检后自动作废。

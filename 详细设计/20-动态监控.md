# 详细设计 20 —— 动态监控

> 所属域：monitor（动态监控台账，**台账上传留存 + 违规识别统计 + 靶向教育联动**）
> 归属系统：`safety`（安全监测系统，区别于 `archive` 归档域——动态监控台账是"安全监测"而非"档案归档"，见 00 架构 domain 表）
> 优先级：**P2 框架**（需求文档二期；档案盒「盒六·动态监控及交通违法管理」为政府必查项，但完整能力后续展开）
> 对应原系统：monitor 子系统「动态监控台账 / 违规处理」（逆向报告 2.x）
> 上游依赖：01 组织权限、10 车辆档案（车辆/驾驶员信息）、14 培训教育（靶向培训联动）
> 下游被依赖：08 归档引擎（盒六·动态监控及交通违法管理）、14 培训教育（违规 → 靶向教育）

---

## 一、模块定位

> **核心界定（用户确认）**：动态监控**不归本系统管理**。车辆卫星定位、超速/疲劳驾驶/偏离线路等实时监测由**外部动态监控平台**（或交警抄报）完成，本系统**只做台账上传留存**，并在此基础上完成一条增值闭环：
>
> **上传台账 → 识别统计违规车辆 → 登记违规驾驶员 → 联动生成针对性违规教育 → 跟踪教育是否落实**。

本系统在动态监控环节承担的是**台账归集与合规闭环**角色，而非实时监控角色：

| 能力 | 是否归本系统 | 说明 |
|------|------------|------|
| 车辆实时定位/监控 | ❌ 不归 | 由动态监控平台负责 |
| 超速/疲劳/偏离线路监测与阈值 | ❌ 不归 | 由动态监控平台负责 |
| 台账上传留存 | ✅ 归 | 导入平台台账/交警抄报并留存 |
| 违规车辆识别统计 | ✅ 归 | 从台账中识别违规车辆并统计 |
| 违规驾驶员登记 | ✅ 归 | 登记违规车辆对应驾驶员 |
| 针对性违规教育联动 | ✅ 归 | 按违规类型生成靶向教育（14） |
| 教育落实跟踪 | ✅ 归 | 跟踪推送→学习→考核→归档闭环 |

> 设计逻辑：把"外部监测的结果台账"沉淀进系统，并据此驱动"违规 → 靶向教育 → 落实"的合规动作，确保政府对"违规是否被教育、是否落实"的必查项在系统内闭环可查。

## 三、核心模型

### 3.1 台账上传留存 + 违规识别统计 + 教育落实（M1~M8）

```
① 上传台账（动态监控平台导出 / 交警抄报 / 人工录入） → 留存
② 系统识别违规车辆（按车牌归并、统计违规次数）
③ 登记违规车辆对应驾驶员（关联 07 人员档案）
④ 联动生成针对性违规教育（14：按违规类型匹配视频）
⑤ 跟踪落实（推送 → 学习 → 考核 → 归档）
⑥ 归档盒六（台账 + 针对性违规教育）
```

> 违规识别、驾驶员登记、靶向教育都复用 07 人员档案、10 车辆档案、14 培训教育已有能力；本模块的增量价值在于**把外部监测结果台账化，并驱动教育落实闭环**。

## 四、数据模型（DDL）

### 4.1 台账留存表 monitor_ledger（M2）

```sql
CREATE TABLE monitor_ledger (
  id              BIGINT PRIMARY KEY,
  tenant_id       BIGINT NOT NULL,
  ledger_name     VARCHAR(200) NOT NULL,        -- 台账名称
  ledger_type     VARCHAR(30),                  -- 类型：工作记录/设备故障/在线率/月报/交警抄报
  source          VARCHAR(30),                  -- 来源：动态监控平台/交警抄报/人工录入
  period          VARCHAR(20),                  -- 周期（如 2026-10）
  file_url        VARCHAR(500),                 -- 附件/文件留存地址
  uploader_id     BIGINT,                       -- 上传人
  uploaded_at     DATETIME DEFAULT NOW(),       -- 上传时间
  violation_count INT DEFAULT 0,                -- 识别出的违规车辆数（冗余统计）
  created_by      BIGINT,
  deleted         TINYINT DEFAULT 0
);
```

### 4.2 动态违规登记表 monitor_violation（M3/M4/M6/M7）

```sql
CREATE TABLE monitor_violation (
  id                  BIGINT PRIMARY KEY,
  tenant_id           BIGINT NOT NULL,
  ledger_id           BIGINT,                   -- 来源台账（monitor_ledger）
  vehicle_id          BIGINT,                   -- 车辆（10 车辆档案）
  vehicle_plate       VARCHAR(20),              -- 车牌（快照）
  driver_id           BIGINT,                   -- 驾驶员（07 人员档案）
  violation_type      VARCHAR(50),              -- 违规类型（引用 violation_dict，14）
  violation_time      DATETIME NOT NULL,        -- 违规时间
  description         VARCHAR(500),             -- 违规说明
  source              VARCHAR(30),              -- 来源：动态监控平台/交警抄报/人工录入
  violation_count     INT DEFAULT 1,            -- 该车辆累计违规次数（统计用）
  status              VARCHAR(20) DEFAULT 'recorded', -- recorded已登记/educated已教育
  education_plan_id   BIGINT,                   -- 关联靶向教育计划（14 training_plan）
  education_status    VARCHAR(20) DEFAULT 'none', -- none未生成/pushed已推送/learning学习中/passed已考核/archived已归档
  education_completed_at DATETIME,              -- 教育落实完成时间（考核通过）
  created_by          BIGINT,
  created_at          DATETIME DEFAULT NOW(),
  deleted             TINYINT DEFAULT 0
);
```

> 违规类型直接引用 14 培训教育的 `violation_dict`；`education_status` 跟踪"推送 → 学习 → 考核 → 归档"闭环是否落实（M7）。

### 4.3 归档映射（M8）

### 4.4 危货电子运单子模块（框架，法律强制）

> 2026.5.1《危险化学品安全法》将电子运单列为**法律强制**。危货每趟运输必须生成电子运单（品类、数量、起止地、承运车辆、驾乘人员信息精准匹配），并上传政府监管平台。电子运单归属**盒六动态监控**的危货扩展（见 08 文档 2.2）。

**核心字段**（电子运单表 `danger_ewaybill`）：

| 字段 | 说明 |
|------|------|
| waybill_no | 运单号（系统生成，对接监管平台） |
| cargo_name | 货物品名 |
| danger_class | 危险类别（易燃/腐蚀/毒害/爆炸/放射性等） |
| un_no | UN 编号 |
| quantity | 数量（吨/件） |
| origin / destination | 起止地 |
| vehicle_id | 承运车辆 |
| driver_id | 驾驶员 |
| escort_id | 押运员（危货强制，全程在岗） |
| status | 运单状态（待发/在途/完成） |

**流程**：

```
① 录入运单 → 生成电子运单（品类/数量/起止地/车辆/人员精准匹配）
② 校验押运员在岗、车辆资质、罐体检验
③ 上传政府电子运单监管平台
④ 归档盒六（电子运单）
```

**与动态监控的关系**：电子运单是危货运输的"过程凭证"，与车辆卫星定位、动态监控**平台**（外部，不归本系统管）联动，形成"运单-车辆-人员-轨迹"全链条追溯（法律要求）；本系统只留存运单结果并归档盒六。

## 六、业务规则

1. **动态监控不归本系统管**：不接入实时定位/监控数据，超速/疲劳/偏离线路等监测阈值由外部平台负责（M1）。
2. **台账只上传留存**：导入平台台账/交警抄报/人工录入，留存后可识别违规（M2）。
3. **违规识别统计**：按车牌归并，累计违规次数（M3）。
4. **驾驶员登记**：违规车辆对应驾驶员关联 07 人员档案（M4）。
5. **违规类型复用 14**：引用 `violation_dict`，不另建字典（M5）。
6. **违规联动靶向教育**：登记后触发 14 靶向教育（M6）。
7. **落实跟踪**：`education_status` 跟踪"推送 → 学习 → 考核 → 归档"闭环（M7）。

## 七、页面交互设计

### 7.1 PC 端（管理端）

**动态监控台账页**（三页签）：
- **台账留存**：台账列表（名称/来源/周期/上传人/时间），「上传台账」导入并留存，识别结果统计
- **违规车辆与驾驶员**：识别出的违规车辆列表（车牌/违规类型/时间/驾驶员/违规次数），「登记违规驾驶员」
- **靶向教育跟踪**：违规驾驶员的教育落实闭环（生成 → 推送 → 学习 → 考核 → 归档）

### 7.2 小程序

无需（台账上传与违规登记为监控员/安全员操作）。

## 十、开发任务拆解

1. 台账上传留存（monitor_ledger + 上传表单）
2. 违规车辆识别统计（按车牌归并 + 次数统计）
3. 违规驾驶员登记（关联 07 人员档案）
4. 违规类型联动（violation_dict，14）
5. 违规 → 靶向教育联动 + 落实跟踪（14，education_status）
6. 归档对接 08（模板 `TPL_MONITOR`）
7. 危货电子运单表 + 运单生成 + 监管平台上传（框架）

> **边界说明（用户确认）**：实时定位/监控、超速/疲劳/偏离线路监测阈值、GPS/视频监控对接**均不归本系统管**，由外部动态监控平台负责；本系统只承接其产出的台账与违规结果。

## 十一、验收标准

1. 可上传并留存动态监控台账（平台导出/交警抄报/人工录入）。
2. 系统能从台账识别并统计违规车辆（按车牌归并、违规次数统计）。
3. 可登记违规车辆对应驾驶员（关联 07 人员档案）。
4. 违规类型复用 14 的 violation_dict。
5. 违规登记后联动生成靶向教育（14），并跟踪"推送 → 学习 → 考核 → 归档"落实闭环。
6. 归档可生成盒六「台账 + 针对性违规教育」PDF。
7. 危货可生成电子运单（品类/数量/起止地/车辆/人员精准匹配），校验押运员在岗。

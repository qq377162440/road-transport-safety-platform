## 一、模块定位

车辆是平台的**第二类核心主数据**。本模块的目标是：**让每辆车最终能自动产出档案盒《一车一档》要求的全部 13 项归档材料**。

> 关键认知（本次修正）：逆向报告的"8 组录入字段"是**录入层**，档案盒标签的"13 项目录"才是**归档交付层**。设计必须以 13 项归档目录为骨架，逐项回答"它由哪些录入字段/哪个业务模块自动生成"。

**边界**：本模块管理"车辆静态档案 + 人车绑定 + 车挂关系"以及它们对应的**归档项生成逻辑**。车辆的动态业务（一日三检、维修保养、行驶里程、主要部件更换）各自独立模块处理，本模块只声明它们会向"一车一档"贡献哪些归档项。

> **普货 vs 危货三处差异**（与 08 文档 2.4 完全一致）：
> 1. 第 4 项：普货="机动车安全技术检验报告"，危货="各类检验报告"（更宽泛，含罐体检验、安全附件检验、专用标识喷涂证明等）
> 2. 第 7 项：危货多"承运人责任险"
> 3. 危货一车一档与普货其余项完全相同（无额外新增项）

### 2.2 归档项产出方式（核心原则：每一项目录最终都必须"有实物"）

> **总原则（用户确认）**：档案盒里每项目录最终都要有实物装盒、能过政府检查。实物产生方式只有三种，且**登记表/记录表类优先自动生成，无数据则打印空白表手写补充**：
>
> | 产出方式 | 含义 | 系统动作 |
> |---------|------|---------|
> | **① 系统生成** | 系统里有数据 → 直接产出最终 PDF | 自动 |
> | **② 企业自备** | 证件/保单/检验报告等实物 → 企业扫描上传 | 上传 |
> | **③ 打印手写** | 系统里**没有数据** → 打印**空白表头/格式**，提示企业手写补充后装盒 | 打印空白模板 |

**13 项归档材料的产出方式分配**：

| 类别 | 归档项 | 产出方式 |
|------|--------|---------|
| ① 系统生成（有数据） | 1 车辆基础信息登记表、6 随车设备清单、8 车辆技术档案、10 等级评定 | 结构化数据**自动生成 PDF** |
| ② 系统生成（有数据）/ 打印手写（无数据） | 11 维修、12 主要部件、13 里程 | 维修保养/里程模块有记录→汇总生成；无记录→打印空白登记表手写 |
| ③ 企业自备 | 2 道路运输证、3 行驶证、4 检验报告、5 登记证、9 GPS证明、7 保险 | 用户**上传扫描件**（OCR 可选回填），证件类无"手写"选项 |

> **降级规则（贯穿全模块）**：凡"登记表/记录表"类归档项，系统先查对应模块有无数据——**有数据→生成成品 PDF；无数据→打印空白格式表，提示"该表无系统数据，请打印后手写补充"**。证件类（②）不适用降级，必须上传实物。

## 三、数据模型（DDL）

> 命名规范对齐 07/08：雪花 ID、`tenant_id`、`deleted` 软删、`created_at/updated_at`、`--` 内联注释。
> **设计原则**：本模块的表 = 支撑"13 项归档目录"所需的最小结构。录入字段仍复用逆向报告 8 组字段，但按归档项重新组织，不再按逆向报告的"8 组折叠卡片"原样照搬。

### 3.1 车辆主表 vehicle（对应归档项 1 的字段来源）

```sql
CREATE TABLE vehicle (
  id              BIGINT PRIMARY KEY,          -- 雪花ID
  tenant_id       BIGINT NOT NULL,
  plate_no        VARCHAR(20) NOT NULL,        -- 车牌号
  plate_color     VARCHAR(10) NOT NULL,        -- 车牌颜色（蓝/黄/绿/白/黑）
  biz_type        VARCHAR(20) NOT NULL,        -- 营运类型：freight/danger/passenger
  vehicle_type    VARCHAR(50),                 -- 车辆类型：牵引车/挂车/货车/客车/罐车...
  vehicle_class   VARCHAR(50),                 -- 车型标签（普货7类/危货两层，见 3.7）
  is_trailer      TINYINT DEFAULT 0,           -- 车/挂：0=车 1=挂
  vehicle_no      VARCHAR(50),                 -- 车辆编号（VEH-0001）
  brand_model     VARCHAR(100),                -- 品牌型号
  vin             VARCHAR(30),                 -- 车辆识别代码VIN号
  engine_no       VARCHAR(50),                 -- 发动机号码
  owner           VARCHAR(100),                -- 所有人
  reg_date        DATE,                        -- 注册日期
  license_no      VARCHAR(50),                 -- 行驶证号（档案号）
  use_nature      VARCHAR(20),                 -- 使用性质
  load_persons    INT,                         -- 核定载人量
  outline_size    VARCHAR(50),                 -- 外廓尺寸
  curb_weight     INT,                         -- 整备质量（KG）
  body_color      VARCHAR(20),                 -- 车身颜色
  energy_type     VARCHAR(20),                 -- 能源类型
  axle_count      INT,                         -- 车轴数量
  tech_level      VARCHAR(10),                 -- 技术等级（一/二/三级）
  business_status VARCHAR(20) DEFAULT 'normal',-- 营运状态：normal/stop/scrap
  stop_start      DATE,                        -- 停运开始日期
  stop_end        DATE,                        -- 停运结束日期（NULL=无限期）
  group_id        BIGINT,                      -- 车辆分组
  created_at      DATETIME DEFAULT NOW(),
  updated_at      DATETIME,
  deleted         TINYINT DEFAULT 0
);
```

### 3.2 车辆文档/证件子表 vehicle_doc（对应归档项 2/3/4/5/9 的证件类）

> 这是"一车一档"归档项 2、3、4、5、9 的统一载体。每类证件一条记录，缺哪类一眼可见（归档完整性校验的基础）。

```sql
CREATE TABLE vehicle_doc (
  id              BIGINT PRIMARY KEY,
  tenant_id       BIGINT NOT NULL,
  vehicle_id      BIGINT NOT NULL,             -- 关联 vehicle
  doc_code        VARCHAR(30) NOT NULL,        -- 文档编码（见 3.6，逐一对齐13项目录）
  doc_name        VARCHAR(100),                -- 文档名称（冗余）
  file_url        VARCHAR(500),                -- 扫描件（对象存储）
  issue_date      DATE,                        -- 发证日期
  expire_date     DATE,                        -- 有效期至（→预警）
  status          TINYINT DEFAULT 0,           -- 0未上传 1已上传 2已过期
  created_at      DATETIME DEFAULT NOW(),
  updated_at      DATETIME
);
```

## 四、归档完整性校验（一车一档的核心价值）

> 这是本模块区别于"普通车辆管理"的关键：**系统能自动判定一辆车的"一车一档"是否齐全**。

### 4.1 校验规则

| 归档项 | 齐全判定 |
|--------|---------|
| 1 车辆基础信息登记表 | `vehicle` 必填字段齐全（车牌/VIN/品牌型号/所有人/注册日期等） |
| 2 道路运输证 | `vehicle_doc` 存在 `CL-DLYSZ` 且未过期 |
| 3 行驶证 | 存在 `CL-XSZ` 且未过期 |
| 4 检验报告 | 存在 `CL-JYBG` 且未过期（危货可多份） |
| 5 登记证 | 存在 `CL-DJZ` |
| 6 随车设备清单 | `vehicle_device` 有记录（含通用清单） |
| 7 保险 | `vehicle_insurance` 含交强险（危货还须含承运人责任险）且未过期 |
| 8 车辆技术档案 | 由维修保养模块数据聚合，有记录即齐全 |
| 9 GPS证明 | 存在 `CL-GPS` |
| 10 等级评定 | `vehicle_grade` 有记录且未过期 |
| 11/12/13 动态台账 | 有相应模块记录即齐全 |

### 4.2 输出

- 每辆车一个**归档完整度百分比**（齐全项 / 应归档项 × 100%）
- 缺项清单 → 推送提醒（如"3 辆车缺道路运输证"）
- 列表页增加"归档完整度"列

## 五、页面交互设计（PC 端）

### 5.1 车辆列表页

- 列表列：车牌号、营运类型、车辆类型、车型标签、车/挂、车辆编号、**归档完整度**、已设置停运
- 筛选：车牌号、营运类型、车辆类型、归档完整度（齐全/缺项）

### 5.2 车辆档案详情页（一车一档视角，核心）

**不再用逆向报告的"8 组折叠卡片"，改为"13 项归档目录"卡片列表**，每项显示：

- 归档项名称 + 是否齐全（✓/✗）
- 对应录入字段或上传入口
- 已上传证件的缩略图/有效期状态

分组呈现（三类）：
- **静态生成区**：1/6/8/10 四项，点"生成 PDF"即时出登记表；若某项无系统数据，则提供"打印空白表"按钮，打印表头格式供手写
- **证件上传区**：2/3/4/5/9 + 7 保险，上传扫描件（无手写选项）
- **动态台账区**：11/12/13 三项，跳转到维修保养/里程模块；有记录→汇总生成，无记录→打印空白登记表手写

### 5.3 车挂关系 tab

- 牵引车视角列出名下挂车；挂车视角显示当前牵引车；建立/解除关联

### 5.4 人车绑定 tab

- 绑定/解绑驾驶员与押运员

### 5.5 与智能资料收集联动

- 批量上传行驶证/道路运输证 → OCR 自动回填 `plate_no/vin/engine_no/brand_model/owner`，并自动登记到 `vehicle_doc` 对应归档项

## 六、业务规则

1. **归档完整度实时计算**：任一项齐全状态变化，实时重算百分比并刷新缺项提醒。
2. **证照到期预警**：`vehicle_doc.expire_date`、`vehicle_insurance.expire_date`、`vehicle_grade.valid_until` 接入统一预警引擎（30/15/7 天分级）。
3. **停运过滤**：`business_status='stop'` 的车辆不生成一日三检任务，但归档完整度仍计算（合规检查不受停运影响）。
4. **车挂唯一性**：同一 `trailer_id` 不允许两条重叠活跃记录。
5. **人车绑定**：同一驾驶员可绑多车；同一辆车当前活跃绑定驾驶员唯一。
6. **车型标签驱动**：`vehicle_class` 决定该车参与哪类检查表/制度规程。
7. **危货差异自动加载**：按 `biz_type=danger` 自动启用"各类检验报告（多份）"和"承运人责任险"两项校验，普货不校验。
8. **登记表类降级（有数据生成/无数据手写）**：凡登记表/记录表类归档项，系统先查有无对应业务数据——有则生成成品 PDF，无则打印空白表头并提示"无系统数据，请打印手写补充"。证件类不适用降级。

## 十、验收标准

1. 能完整录入一辆车并自动生成 13 项归档目录的完整性视图。
2. 每辆车能实时显示"归档完整度百分比 + 缺项清单"。
3. 危货车辆自动启用"各类检验报告（多份）+ 承运人责任险"校验，普货不启用。
4. 静态类归档项（1/6/8/10）能一键生成 PDF。
5. 证照/保险/等级任一到期，预警引擎按 30/15/7 天分级触发。
6. 牵引车与挂车能建立/解除关联，不出现一挂多主。
7. 停运车辆不进入一日三检，但归档完整度仍计算。
8. 车辆软删除后，历史归档项仍能关联回查。

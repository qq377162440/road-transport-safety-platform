# 详细设计 01 —— SSO 统一认证 + 组织权限体系

> 版本：v1.0
> 日期：2026-10-27
> 状态：可进入开发
> 设计粒度：业务规则 + 数据模型 + 接口 + 状态流转 + 页面交互 + 表结构

---

## 一、模块定位（第一性原理）

本模块是整个平台的「地基」，解决两个根本问题：

1. **谁是谁**（认证 Authentication）—— 证明登录者身份合法
2. **谁能干什么**（授权 Authorization）—— 控制每个角色能看什么、能点什么

> 关键结论：认证 + 授权是**所有后续模块的前置依赖**，必须先定清楚，否则后面每个模块都要返工。

---

## 二、关键架构决策

### 2.1 不照搬原系统的微服务 SSO

原系统是「5 个独立子系统 + passport 认证中心」的微服务架构，登录后要逐个子系统下发 token 建立会话。但我们的选型是**单体模块化**（一个后端、按业务模块分包），因此：

| 原系统做法 | 我们采用 | 原因 |
|-----------|---------|------|
| 独立 passport 认证中心，跨域下发多子系统 token | 单体应用内统一 `/auth` 认证 + JWT | 无需跨域同步，降低复杂度 |
| JSESSIONID 会话 + 各子系统各自会话 | 无状态 JWT + Redis 白名单 | 易扩展、易横向扩容 |
| 图形验证码手动识别 | 图形验证码（可选短信验证码） | 保留原交互，增强安全性 |

> **决策**：认证逻辑内聚在单体后端的 `auth` 模块，通过 JWT 传递身份。未来若真拆微服务，只需把 `/auth` 独立成认证服务，其余模块无感。

### 2.2 多租户隔离

平台面向「运营方 → 多个运输企业」，天然多租户。数据隔离采用**字段级隔离**（每张业务表带 `tenant_id`），通过 MyBatis-Plus 的租户插件自动注入。

| 租户层级 | 说明 |
|---------|------|
| 运营方（平台） | 顶级，管理所有企业 |
| 企业（租户） | 独立数据域，互不可见 |
| 集团/子企业 | 企业分组（一个企业下可再分子企业） |

## 三、角色与权限模型（RBAC）

### 3.1 核心概念

```
用户(User) ——多对多——> 角色(Role) ——多对多——> 权限(Permission)
                              |
                              +—— 菜单(Menu) + 按钮(Button)
```

- **用户**：登录账号，归属于某个企业（租户）
- **角色**：权限的集合，如「企业管理员」「安全员」「驾驶员」「法人/负责人」
- **权限**：最小授权单元，分「菜单权限」（能不能看到）+「按钮/接口权限」（能不能操作）

### 3.2 内置角色（预设，可扩展）

| 角色 | 端 | 核心权限 |
|------|-----|---------|
| 企业管理员 | PC | 全部菜单 + 用户/角色管理 |
| 法人/负责人 | PC + 小程序(管理视角) | 查看全局数据、审批、督办 |
| 安全员/管理人员 | PC + 小程序(管理视角) | 安全工具、隐患、会议、培训、档案 |
| 驾驶员/从业人员 | 小程序(司机视角) | 三检、学习、签到、报修、查证照 |
| 押运员 | 小程序(司机视角) | 同驾驶员（部分差异） |
| 服务商账号 | PC | 企业管理、计费、**系统配置管理（模板/范本库、视频库、题库、字典、预警规则等）**、**修改所有台账记录 + 录入即生成台账** |
| 平台超级管理员 | PC | 顶级：创建/管理服务商账号（渠道商）、全量数据权限 + 规则配置 + 纠错 |

> **服务商账号 = 平台侧服务商/渠道商账号**（非"代录专员"）。其核心职责是**管理整个系统所有的模板、范本库、视频库、题库、字典、预警规则等配置**，类似平台后台的普通管理员；同时**拥有修改所有台账记录的权限，可通过录入直接生成对应台账**（无需真实执行流程，即"代录"能力）。服务商账号 ≠ 代录角色——代录/录入生成只是其能力之一。

> **服务商账号与平台超级管理员的关系（渠道商模型）**：平台超级管理员是**顶级账号**，可**创建多个服务商账号**——每个服务商账号对应一个**渠道商/服务商**，服务其名下的一批企业。这是平台"发展渠道商"的账号基础。

### 3.3 权限粒度

| 粒度 | 示例 | 实现 |
|------|------|------|
| 菜单 | 能看到「隐患排查治理」菜单 | 菜单表 + 角色关联 |
| 按钮 | 能点「删除隐患」 | 按钮编码 + 前端 v-if + 后端 @PreAuthorize |
| 数据 | 只能看本部门/本车组 | 数据权限（见 3.4） |

### 3.4 数据权限（原系统实测的「角色权限/车组权限」）

原系统人员档案里有「角色权限（角色1/2/3 查看）」「车组权限（车组1/2/3 查看）」。我们抽象为**数据范围**：

| 数据范围 | 说明 |
|---------|------|
| 全部数据 | 企业管理员 |
| 本部门数据 | 部门负责人 |
| 本车组数据 | 车队长 |
| 仅本人数据 | 驾驶员 |

## 四、登录与认证流程

### 4.1 登录流程（PC + 小程序统一）

```
用户输入账号+密码+图形验证码
    → POST /auth/login 校验
    → 校验通过，生成 JWT（含 userId、tenantId、roles）
    → JWT 存入 Redis 白名单（可主动失效）
    → 前端保存 token，后续请求带 Authorization: Bearer <token>
    → 前端根据角色渲染菜单（菜单接口按角色返回）
```

### 4.1.1 账号身份自动识别（无需选择角色）

登录页**不展示角色下拉**，系统按账号前缀自动识别身份：

| 账号前缀 | 识别身份 | 角色 |
|---------|---------|------|
| `aa` | 企业账号 | `enterprise` |
| `bb` | 服务商账号 | `provider` |
| `cc` | 平台超级管理员 | `admin` |

- 校验通过后写入 `userRole` 与 `userName`，按角色动态渲染侧边栏菜单（企业 / 服务商 / 超管可见菜单不同）。
- 演示环境三账号密码任意；正式环境走账号密码 + 图形验证码 + JWT（见 4.1~4.3）。

### 4.2 图形验证码

- `GET /auth/captcha` 生成 4 位字符验证码，返回 `{ uuid, base64Image }`
- 验证码存入 Redis，有效期 5 分钟，一次性（校验后立即失效）
- 登录失败后需重新获取验证码

### 4.3 Token 设计

| 项 | 值 |
|----|-----|
| 格式 | JWT（HS256 签名） |
| 载荷 | `{ userId, tenantId, username, roles[] }` |
| 有效期 | access_token 2 小时，refresh_token 7 天 |
| 存储 | Redis 白名单，key = `auth:token:{userId}`，支持主动踢下线 |

### 4.4 状态流转

```
禁用 ──启用──> 启用 ──登录──> 在线 ──登出/踢下线──> 离线
  ▲                                              │
  └──────────── 管理员禁用 ────────────────────────┘
```

### 4.5 代登（Impersonation）：服务商 / 超管 进入企业账号

- **服务商一键代登**：在「企业管理」左侧企业列表点"一键登录企业"，系统写入代登上下文（`impersonating` + 企业 ID + 服务商标识），直接进入该企业账号；顶部显示"返回服务商账号"横幅，点之即回。
- **超管切换服务商**：超管可在服务商列表间切换，再代登其名下企业。
- 代登仅改变"当前操作视角"，**不转移数据所有权**，企业数据始终归属原租户；操作留痕记入 `sys_oper_log`。

### 4.6 新增企业自动创建主账号（交付标准动作）

服务商在「企业管理」**新增企业**时，系统**自动创建该企业主账号**：

- **用户名 = 企业名称全称**（如 `佛山市悦通物流有限公司`）
- **初始密码 = `888888`**（企业可登录后在"账号管理"中修改）
- 同时生成「安全员」「驾驶员」等默认子账号（初始密码同 `888888`），企业可按需启用 / 停用
- **禁用企业 → 同步禁用其全部账号**（一键登录置灰）；启用后恢复。密码修改、账号启用 / 停用均经 `sys_user` 接口，状态变更实时同步电子档案柜企业视角。

### 4.7 小程序端登录与人员账号自动开通

小程序端服务对象是**一线从业人员**（司机 / 押运员 / 安全员 / 管理员），登录与开通规则与 PC 端企业账号体系同源但更轻量：

**登录规则**
- 登录账号 = **人员手机号**，初始密码 = **123456**（首次登录强制改密）。
- 无需选择企业 / 角色：手机号即唯一标识，系统据 `person` 主表绑定的企业 + 岗位自动判定租户与角色，按角色渲染首页。

**录入即开通（自动化）**
- 在 PC 端「人员基础信息 / 人车管理」录入人员（姓名 / 手机号 / 岗位）时，**所有岗位自动开通**小程序端账号，无需单独建号。
- 账号状态与人员状态联动：人员离职 / 停用 → 小程序账号同步停用；启用后恢复。人档车档保留 ≥ 3 年。

**按岗位职责显示不同功能**

| 岗位（职责） | 小程序端可见功能 |
|------|------|
| 驾驶员 / 押运员 | 一日三检、行车日志、报修车、报隐患、签文件（责任书 / 承诺书）、查考核、学习中心（视频 + 答题） |
| 安全员 / 安全管理人员 | 督办隐患、证件到期提醒、三检统计、下发任务、安全数据看板、会议管理、人员管理 |
| 企业管理员 | 全部管理功能 + 企业安全管理驾驶舱 |

## 五、数据模型（表结构）

### 5.1 表清单

| 表名 | 说明 |
|------|------|
| `sys_tenant` | 企业（租户）表 |
| `sys_user` | 用户表 |
| `sys_role` | 角色表 |
| `sys_menu` | 菜单/权限表 |
| `sys_user_role` | 用户-角色关联 |
| `sys_role_menu` | 角色-菜单关联 |
| `sys_dept` | 部门表 |
| `sys_group` | 企业分组/车组表 |

### 5.2 关键表结构（DDL 级）

```sql
-- 企业（租户）
CREATE TABLE sys_tenant (
  id          BIGINT PRIMARY KEY,           -- 雪花ID
  name        VARCHAR(100) NOT NULL,        -- 企业名称
  credit_code VARCHAR(50),                  -- 统一社会信用代码
  status      TINYINT DEFAULT 1,            -- 1启用 0禁用
  expire_time DATETIME,                     -- 服务到期时间
  created_at  DATETIME DEFAULT NOW()
);

-- 用户
CREATE TABLE sys_user (
  id          BIGINT PRIMARY KEY,
  tenant_id   BIGINT NOT NULL,              -- 所属企业
  username    VARCHAR(50) NOT NULL UNIQUE,  -- 登录账号
  password    VARCHAR(100) NOT NULL,        -- BCrypt 加密
  real_name   VARCHAR(50),                  -- 真实姓名
  phone       VARCHAR(20),                  -- 手机号
  user_type   VARCHAR(20),                  -- 用户类型：驾驶员/安全员/法人...
  status      TINYINT DEFAULT 1,            -- 1启用 0禁用
  dept_id     BIGINT,                       -- 所属部门
  created_at  DATETIME DEFAULT NOW()
);

-- 角色
CREATE TABLE sys_role (
  id          BIGINT PRIMARY KEY,
  tenant_id   BIGINT NOT NULL,              -- 角色归属（0=运营方内置）
  role_code   VARCHAR(50) NOT NULL,         -- 角色编码：ADMIN/SAFETY/DRIVER...
  role_name   VARCHAR(50) NOT NULL,
  is_builtin  TINYINT DEFAULT 0,            -- 是否内置角色（不可删）
  data_scope  TINYINT DEFAULT 1,            -- 数据范围：1全部 2部门 3车组 4本人
  created_at  DATETIME DEFAULT NOW()
);

-- 菜单/权限（同时承载菜单树 + 按钮权限）
CREATE TABLE sys_menu (
  id          BIGINT PRIMARY KEY,
  parent_id   BIGINT DEFAULT 0,             -- 父级，0=根
  menu_name   VARCHAR(50) NOT NULL,         -- 显示名
  menu_type   TINYINT NOT NULL,             -- 1目录 2菜单 3按钮
  perms       VARCHAR(100),                 -- 权限标识：danger:delete
  path        VARCHAR(100),                 -- 前端路由
  sort        INT DEFAULT 0,
  visible     TINYINT DEFAULT 1
);

-- 用户-角色
CREATE TABLE sys_user_role (
  user_id BIGINT NOT NULL,
  role_id BIGINT NOT NULL,
  PRIMARY KEY (user_id, role_id)
);

-- 角色-菜单
CREATE TABLE sys_role_menu (
  role_id BIGINT NOT NULL,
  menu_id BIGINT NOT NULL,
  PRIMARY KEY (role_id, menu_id)
);

-- 部门
CREATE TABLE sys_dept (
  id         BIGINT PRIMARY KEY,
  tenant_id  BIGINT NOT NULL,
  parent_id  BIGINT DEFAULT 0,
  dept_name  VARCHAR(50) NOT NULL,
  sort       INT DEFAULT 0
);

-- 企业分组/车组
CREATE TABLE sys_group (
  id         BIGINT PRIMARY KEY,
  tenant_id  BIGINT NOT NULL,
  group_name VARCHAR(50) NOT NULL,
  group_type VARCHAR(20),                   -- 车队/线路/其它
  created_at DATETIME DEFAULT NOW()
);
```

## 六、接口定义

### 6.1 认证接口

| 方法 | 路径 | 说明 | 入参 | 出参 |
|------|------|------|------|------|
| POST | `/auth/captcha` | 获取图形验证码 | — | `{ uuid, image }` |
| POST | `/auth/login` | 登录 | `{ username, password, captchaUuid, captchaCode }` | `{ token, userInfo }` |
| POST | `/auth/logout` | 登出 | — | — |
| POST | `/auth/refresh` | 刷新 token | `{ refreshToken }` | `{ token }` |
| GET | `/auth/me` | 获取当前用户信息 | — | `{ user, roles, menus }` |

### 6.2 用户管理接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/user/page` | 分页查询用户 |
| POST | `/api/user` | 新增用户 |
| PUT | `/api/user/{id}` | 编辑用户 |
| DELETE | `/api/user/{id}` | 删除用户 |
| PUT | `/api/user/{id}/status` | 启用/禁用 |
| PUT | `/api/user/{id}/reset-pwd` | 重置密码 |
| PUT | `/api/user/{id}/roles` | 分配角色 |

### 6.3 角色/菜单接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/role/page` | 分页查询角色 |
| POST | `/api/role` | 新增角色 |
| PUT | `/api/role/{id}` | 编辑角色 |
| DELETE | `/api/role/{id}` | 删除角色（内置角色不可删） |
| PUT | `/api/role/{id}/menus` | 分配菜单权限 |
| GET | `/api/menu/tree` | 获取菜单树（按当前用户角色） |

## 七、页面交互设计

### 7.1 登录页（PC + 小程序统一逻辑）

- 账号、密码、4 位图形验证码（点击刷新）
- 登录失败提示：账号或密码错误 / 验证码错误
- 登录成功跳转：PC → 驾驶舱；小程序 → 按角色渲染首页

### 7.2 用户管理页（PC）

- 列表：用户名、姓名、企业分组、角色、状态、操作
- 筛选：用户名、状态
- 新增用户弹窗：用户名、密码、姓名、手机号、角色、企业分组、状态
- 操作：编辑、重置密码、启用/禁用、分配角色

### 7.3 角色管理页（PC）

- 角色列表 + 新增/编辑/删除
- 权限分配：菜单树勾选（目录 + 菜单 + 按钮三级）

## 八、非功能性约束

| 项 | 要求 |
|----|------|
| 密码存储 | BCrypt 加密，禁止明文 |
| 验证码 | 一次性，5 分钟过期 |
| 登录失败 | 连续 5 次锁定账号 15 分钟 |

| 留痕 | 登录日志、操作日志入库 |

## 十、验收标准

1. 账号 + 密码 + 图形验证码能正常登录，错误验证码/密码有明确提示
2. 不同角色登录后，菜单和按钮按权限正确显示/隐藏
3. 用户管理能完成增删改查、禁用、重置密码、分配角色
4. 企业 A 的用户无法看到企业 B 的任何数据
5. 连续错误登录会触发锁定

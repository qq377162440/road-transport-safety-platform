# 用户手册 · 服务商版

> 适用对象：服务商运营/交付人员、平台超级管理员
> 版本：v1.0.0-prod（E3）
> 对应《产品需求确认文档》§十一「企业签约后的完整交付与运营流程」

---

## 1. 角色与入口

| 角色 | 账号示例 | 可见范围 |
|---|---|---|
| 服务商 | `bb_provider` | 全部企业的代录、范本、课程、接入看板、反馈处理 |
| 平台超管 | `cc_admin` | 上述全部 + 企业开通、系统运维 |

两个角色都是**平台级账号**，跨租户查询；企业账号只能看到自己租户的数据。

## 2. 签约开户（阶段 0）

### 方式 A：网页（`/onboarding`）

「＋ 签约开户」填写：企业全称、统一社会信用代码、营运类型（普货 GENERAL / 危货 DANGER）、所属地区、安全主要负责人、电话、合同起止。

系统自动完成：

| 动作 | 产出 |
|---|---|
| 建租户 | `sys_tenant`，合同到期写入 `expire_time`（续费依据） |
| 建企业信息骨架 | `tenant_info` |
| 建主账号 | 用户名 = 企业全称，初始密码 `888888`，绑定企业角色 |
| 建默认岗位 | 从平台 12 职能字典生成，总经理为根，总经理/安全员/监控员为强制岗位 |
| 建接入状态 | 六阶段 26 项检查项进度，阶段 0 的签约/建号/配置自动完成 |
| 建档案盒 | 目录为平台统一模板（普货 10 盒 / 危货 11 盒），无需逐企业复制 |

> **必须提醒企业首次登录后立即修改初始密码**。企业名称超过 45 字时，登录名自动回退为统一社会信用代码，开户结果里会明确显示。

### 方式 B：命令行（交付现场批量开户）

```bash
cd server/deploy
./open_account.sh "企业全称" "统一社会信用代码" [GENERAL|DANGER] [地区] [负责人] [电话]
# 例：./open_account.sh "XX运输有限公司" "91440600XXXXXXXXXX" GENERAL 佛山市 张经理 13800000000
```

输出租户 ID、主账号、初始密码、岗位与检查项数量。默认用 `bb_provider` 登录，可用 `PROVIDER_USER` / `PROVIDER_PASS` / `BASE_URL` 覆盖。

## 3. 六阶段接入引导（`/onboarding`）

对齐需求 §十一，进度条与检查项逐项可跳转：

| 阶段 | 名称 | 关键动作 | 主要跳转 |
|---|---|---|---|
| 0 | 签约与开户 | 商务签约、新增企业、营业执照上传、开通配置 | `/onboarding`、`/company` |
| 1 | 资料采集 | 企业三步自助填报、现状诊断、必要时服务商代录 | `/m/onboard`、`/collect` |
| 2 | 静态资料全面整改 | 架构/24 项制度/应急预案/四类计划/三书/岗前培训 | `/org`、`/template-manager`、`/responsibility` |
| 3 | 小程序全员账号开通 | 录入手机号即开通、岗位差异化、离职停用联动 | `/biz/person`、`/post` |
| 4 | 制度与台账归档就位 | 制度发布签署、11 盒自检、整套 PDF 下载 | `/archive`、`/archive-overview` |
| 5 | 日常运营与年审续签 | 三检/会议/培训/隐患/监控台账、自然年度重签、续费 | `/m/check`、`/onboarding` |

勾选检查项后系统自动重算当前阶段：阶段 = 第一个仍有必做项未完成的阶段；全部完成进入「运营中」。可选检查项（`S1_COLLECT` 代录、`S3_STATUS` 离职联动、`S5_MONITOR` 监控台账）不阻塞推进。

**企业接入看板**列出全部企业的阶段、状态、检查项完成率、合同到期时间，便于管理上百家客户。

## 4. 归档就位自检（阶段 4）

选中企业 → 「归档就位自检」，逐项返回期望值/实际值/是否通过：

- 档案盒目录齐全（普货 10 / 危货 11）
- 已产生归档项
- 人员档案、车辆档案
- **人员/车辆档案归档项是否挂到正确租户**（铁律 6，服务商代录时尤其要查）
- 制度类归档
- 接入检查项已推进

自检耗时通常 < 10ms，可直接作为交付验收依据（也是验收标准 ② 的机器化复测入口）。

## 5. 代录工作台（`/collect`）—— 验收标准 ④

面向不会用系统的小微个体户：

1. 建代录任务（`collect_task`）。
2. 上传照片/表格，填写行数据。
3. **跳过起草推送**、复用历史签字，直接落业务表。
4. 每条记录自动登记归档项（显式指定目标租户，不会挂到平台名下）。

对应验收标准 ④：小微个体户在服务商代录下快速补齐整套台账。

## 6. 范本套管理（`/template-manager`）

建套 → 设默认 → 起草推送 → 企业执行。制度字典为 24 项 `YT-ZD01~24`，责任制与岗位名称联动；变量字段填充、在线改、年度更新、盖章签字均在此配置。

## 7. 课程下发与培训（`/biz/training`）

课程库选课下发 → 学员看视频 + 答题考核 → 学时统计与考试留痕。支持岗前/岗中/靶向教育；线上学习已通过 1000 并发压测。

## 8. 自定义文件签署（`/flow-tools`）

拖拽盖章/签名锚点 → PDF 合成。签署凭证 PDF 可直接归档。

## 9. 试运行反馈处理（`/feedback`）

平台视角可看全量反馈；对未闭环项点「处理」：

- `待受理 → 处理中`：记录复现与排期
- `处理中 → 已解决`：写明修复版本
- `待受理/处理中 → 已驳回`：写明理由（如「实为操作咨询」）

已闭环反馈不可重复处理。汇总卡展示总数、未闭环、已闭环、解决率，可按状态/类型筛选。`trial_report.py` 会把这些真实数据生成《试运行演练报告》。

## 10. 运维命令（部署机上）

```bash
cd server/deploy
./backup_cron.sh       # 每日冷备 + 完整性校验 + 异地同步 + 14 天保留清理
./monitor.sh           # 6 类巡检，异常推送告警；0=正常 1=异常
./restore.sh backups/<时间戳> -y    # 覆盖式恢复
./trial_run.sh         # 试运行演练 + 四条标准计时 + 生成报告
```

详见 `server/deploy/生产部署与运维手册.md` 与 `README.md`。

## 11. 常见问题

| 问题 | 处理 |
|---|---|
| 开户提示「统一社会信用代码重复」 | 该企业已开户，去接入看板查找；如需重新签约先联系超管处理旧租户 |
| 开户提示「登录账号已存在」 | 企业全称与已有账号重名，改用例外名称或让超管清理 |
| 企业填报卡在某一步 | 在接入看板选中企业看 `step`（0~3）与检查项完成情况；必要时用代录工作台跳过 |
| 阶段一直不推进 | 检查是否还有**必做**检查项未勾选；可选项不影响 |
| 代录后档案柜看不到记录 | 用「归档就位自检」确认归档项租户归属；本版本已修复代录挂到平台名下的问题 |
| 企业反馈看不到 | 企业只能看本租户反馈；平台用服务商/超管账号查看全量 |
| 合同到期后怎么办 | `sys_tenant.expire_time` 为续费依据，到期预警在阶段 5 检查项 `S5_RENEW` |

- [ ] 三步接入填报完成、现状诊断已确认

- [ ] 全员手机号账号开通、岗位可见性校验

- [ ] 阶段 5 日常运营已跑通一次三检/会议
- [ ] 试运行反馈无致命级未闭环项

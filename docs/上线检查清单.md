### 诚实边界说明

本清单中 ✅ 项为**沙箱内真实执行并验证**的结果；⏳ 项依赖真实外部资源（域名、证书、服务器、告警通道、真实种子客户、人员签字），沙箱无法代替，已逐项标注为上线阻断项。当前演练版试运行报告的反馈数据由脚本构造，不能作为真实试运行结论。

### E4 连续复测暴露并修复的缺陷

上线复测要求「可从任意时点重复运行」，连续重跑暴露了 5 个真实问题，均已修复并回归验证：

1. **匿名接口限流**：原为同 IP 下所有 `/api/auth/**` 共享 20 次/60s，刷新验证码会挤占登录配额；企业办公室共享出口 IP、早高峰集中登录会被自己的限流挡住。改为按「IP + 端点」分桶，阈值经 `RATE_LIMIT_MAX` / `RATE_LIMIT_WINDOW` 可配置，默认 60/60s。
2. **复测脚本中断**：`go_live_check.sh` 的 `run_suite()` 同行 `local` 声明在 `set -u` 下触发未绑定变量；并新增限流窗口对齐等待（只等窗口自然过期，不删计数键、不绕过限流）。
3. **B7 断言重跑失败**：「缺项提示 / 批量生成」硬编码 `>0`，而批量生成为幂等补齐，跑过一次后必然归零；改为校验数组结构、生成数不超过缺项数、二次调用幂等。
4. **限流断言失效**：循环次数写死 22，阈值调高后不再触发 429；改为跟随 `RATE_LIMIT_MAX`。
5. **开户套件重跑冲突**：固定企业名导致 `3002 登录账号已存在`；企业名按信用代码后缀唯一化；`Dockerfile.e2e` 补 `COPY go_live_check.sh`。

> 以上为上线前置的工程可靠性改进，不改变业务功能。修复后**连续两轮正式复测均为 14/14 全绿**（基线 7 项 + 四条标准 + 三套回归）。

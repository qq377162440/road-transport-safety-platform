# 培训材料与试运行方案

> 对应计划 E3「企业版/服务商版手册、培训材料、种子客户试运行反馈闭环」
> 配套文档：[用户手册 · 企业版](用户手册-企业版.md)、[用户手册 · 服务商版](用户手册-服务商版.md)

## 一、培训目标

1. 让**不会用电脑的中老年司机**能独立完成一日三检（验收标准 ①）。
2. 让**安全员**能在政府检查时快速调出完整台账（验收标准 ②）。
3. 让**企业负责人**能看懂驾驶舱的最紧急风险（验收标准 ③）。
4. 让**服务商交付人员**能独立完成签约开户 → 六阶段交付 → 归档自检（验收标准 ④）。

## 二、分角色课程大纲

| 对象 | 时长 | 内容 | 实操任务 | 考核 |
|---|---|---|---|---|
| 驾驶员 | 20 min | 登录（手机号 + 初始密码）、`/m/check` 三步三检、异常上报 | 完整做一次出车前三检 | 30 秒内完成 |
| 安全员 | 60 min | 企业信息、组织架构与岗位、三检任务下发、隐患整改验收、会议四段式、档案柜全景与缺项 | 调出整套台账 PDF、闭环一条隐患 | 5 分钟内调档 |
| 企业负责人 | 30 min | 首次接入三步填报、责任制生成、风险驾驶舱、年度重签、反馈提交 | 完成三步填报、读出当前安全分 | 能说出最紧急风险 |
| 服务商交付 | 90 min | 签约开户（网页 + 命令行）、六阶段引导、代录工作台、范本套、课程下发、归档自检、反馈处理 | 独立开户一家企业并推进到归档就位 | 自检全部通过 |
| 运维 | 45 min | 生产编排、HTTPS 证书、备份/恢复、监控告警、回滚 | 执行一次备份 + 恢复演练 | RTO ≤ 30min |

**培训形式**：线上一讲一练 + 纸质速查卡（企业版手册第 14 节可直接打印）。驾驶员培训建议在出车现场用手机完成，不在教室讲 PPT。

## 三、四条验收标准演练脚本

> 正式复测由 E4 `go_live_check.sh` 自动执行；本节用于培训现场人工演练。
> 演练前需准备好：演示企业账号、一名驾驶员账号、一个三检任务、至少一条人员与车辆档案。

| # | 标准 | 前置 | 步骤 | 判定 | 对应接口 |
|---|---|---|---|---|---|
| ① | 30 秒完成一次三检 | 已下发三检任务 | 手机打开 `/m/check` → 选任务 → 选「出车前」→ 点「合格」 | 全程 ≤ 30s 且返回结果提示 | `flow/check/task`、`flow/check/record` |
| ② | 5 分钟调出完整台账 | 已有归档项 | `/archive-overview` 看 10/11 盒全景与缺项 → 批量生成 → 下载整套 PDF | 全程 ≤ 5min，PDF 可打开 | `flow/archive/overview`、`archive/missing`、`archive/batch-generate` |
| ③ | 一眼看出最紧急风险 | 已产生隐患/缺项 | 登录首页或 `/risk-dashboard` | 展示安全分与最紧急风险 | `flow/dashboard/risk` |
| ④ | 服务商代录补齐台账 | 服务商账号 | `/collect` 建代录任务 → 填行数据 → 跳过推送直接落业务表 | 记录出现在业务表且归档项归属正确 | `biz/collect_task`、`flow/collect/{id}/fill` |

**计时方式**：`trial_run.sh` 用毫秒时间戳对每条链路计时并写入 `试运行演练报告.md`；人工演练可用手机秒表。

## 四、试运行方案

### 4.1 种子客户选取

| 维度 | 建议 |
|---|---|
| 数量 | 3~5 家，覆盖普货 / 危货 / 小微个体户 |
| 覆盖角色 | 每家至少 1 名负责人 + 1 名安全员 + 2 名驾驶员 |
| 覆盖场景 | 首次接入填报、日常三检、会议、隐患、档案柜检查、服务商代录 |
| 周期 | 2~4 周，其中至少含 1 次完整的月度归档自查 |

### 4.2 反馈闭环机制（系统内已落地）

```
企业/服务商提交（/feedback）
   → 平台受理 processing
   → 解决 resolved / 驳回 rejected（写处理说明与处理人）
   → 汇总统计（解决率、按类型/模块分布、未闭环清单）
   → 生成报告（trial_report.py）
```

- 企业只能看本企业反馈，平台看全量（已在验收脚本中验证隔离与越权拦截）。
- 已闭环反馈不可重复处理（状态机硬约束）。
- 每条反馈记录级别（致命 / 一般 / 轻微）；**致命级未闭环 = 上线阻断项**。

### 4.3 判定标准与退出条件

| 项 | 上线门槛 |
|---|---|
| 四条验收标准 | 全部 PASS，且耗时达标（30s / 5min） |
| 致命级反馈 | 0 条未闭环 |
| 一般级反馈 | 解决率 ≥ 80%，剩余项有明确责任人与上线后处理时限 |
| 核心链路回归 | 闭环 10/10、全链路 38/38、开户引导 29/29、单元测试全通过 |
| 备份与回滚 | 恢复演练成功、回滚演练成功（E4） |
| 生产资源 | 域名/备案、CA 证书、告警 webhook、异地备份目标全部就位（E1 ⏳ 项） |

### 4.4 演练执行

```bash
cd server/deploy
./trial_run.sh        # 模拟种子客户反馈 + 四条标准计时 + 生成报告
```

报告输出 `docs/试运行演练报告.md`。**注意**：沙箱内运行产生的是演练构造数据，不是真实种子客户反馈；正式试运行需用真实客户数据重跑，并把真实报告作为 E4 上线检查附件。

## 六、与 E4 的衔接

E3 交付培训与试运行能力；E4 负责**正式复测**：`go_live_check.sh` 对四条标准做带 PASS/FAIL 断言的复测，并把本报告的真实版本、生产资源就位情况、备份/回滚演练结果一并纳入《上线检查清单》签字。
